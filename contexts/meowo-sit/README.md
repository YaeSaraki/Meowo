# Sit / Ride

`/sit` 切换坐下与起身；需脚下有地面。座位使用插件自有的不可见盔甲架，起身、退出和模块停用时清理。

`/ride [玩家]` 骑乘附近玩家，省略参数则脱离；也可潜行脱离。需要 `meowo.ride` 权限（默认开放），无权限显示错误。骑乘不收费，管理员也不能绕过范围检查。

补全与执行使用相同的合法性检查，只提供在线、存活、可见、同世界的玩家。范围以自身位置为中心，X、Y、Z 距离均不超过 1.5 格：水平为 3×3 的正方形，并排除其他楼层的目标。`sit.target-range` 表示区域宽度，默认 3；旧配置大于 3 时自动封顶，可设得更小。

目标已有玩家骑乘时，逐层找到最上面的玩家，再将自己骑在其上。链上每个玩家都必须在范围内、可见且处于可骑乘状态；非玩家乘客、多个乘客的分支、已在链上的玩家或任何循环都拒绝。失败不会拆散原有乘客链。命令执行时重新检查，避免补全后目标走远。

只支持玩家目标；旧 `meowo.ride.any` 权限不再启用生物骑乘。

## 右键坐在方块上

空手右键楼梯、半砖或地毯即可坐下；手持物品时不触发，避免劫持开箱子和放方块的点击，
且只有真正坐下才 `cancel()` 事件。判定用 `Tag.STAIRS` / `Tag.SLABS` / `Tag.WOOL_CARPETS`，
因此模组方块也能生效（这些 Tag 在 MockBukkit 里真实可用，已实测）。

座位位置 = 方块中心 + **Y 偏移** + **前移量**，前移方向分两种：

- **楼梯**：用楼梯自己的朝向，不用玩家朝向
- **半砖 / 地毯**：用玩家当前朝向

### 楼梯要看朝向

Minecraft 里 `facing` 是楼梯**整格面**的方向，而放置时「半格面总是朝向玩家」，
所以**台阶在 `facing.getOppositeFace()`**。玩家站在台阶一侧往方块看时，
他的朝向恰好和台阶**相反**——因此落座偏移必须以楼梯朝向为准，否则椅子会坐到整格那一侧。

两种楼梯会被拒绝（各有独立提示，不会静默失败）：

| 情况 | 原因 |
|---|---|
| 上下颠倒的楼梯（`half=top`） | 台阶变成了天花板，没有可坐的台面 |
| 从整格面一侧靠近 | 台阶在方块另一面，椅子会埋进高的那一半 |

> **踩过的坑**：`Stairs` 确实有 `getFacing()` / `getHalf()`，但它们继承自
> `Directional` / `Bisected`。只 `grep Stairs.class` 会搜不到，误以为 API 没了。
> 核实方法要用 `javap -p` 并顺着 `extends` 追父接口。
> 真正拿不到的是**地毯**的精确高度：26.2 没有通用的 `Carpet` 数据类（只有 `MossyCarpet`）。
> 这才是「每类方块一个可配置偏移」这一做法真正的原因。

**三种方块是三个不同的高度**，因为它们本来就是三种不同的表面：

| 方块 | 表面 | `*-offset-y` | 理由 |
|---|---|---|---|
| 楼梯 | 下阶 y+0.5 | `0.1` | 三者中最高，作基准 |
| 半砖 | 薄搁板 y+0.5 | `-0.15` | 比楼梯的台阶薄，座位略低 |
| 地毯 | 贴地 y+1/16 | `-0.5` | 只有 1/16 格，必须紧贴地面 |

> 偏移是相对**方块中心（y+0.5）**，不是相对表面，所以地毯需要一个明显为负的值。

前移距离也按深浅区分：楼梯最宽所以前移最多，半砖只有半格深所以收一点，地毯贴地不前移。

```yaml
sit:
  right-click-blocks: true
  max-distance: "4"
  stair-offset-y: "0.1"
  slab-offset-y: "-0.15"
  carpet-offset-y: "-0.5"
  stair-forward: "0.35"
  slab-forward: "0.2"
  carpet-forward: "0"
```

Minecraft 的朝向向量是 `(-sin, 0, cos)`：yaw 0 朝 +Z，-90 朝 +X。该计算抽成纯函数
`seatAnchor(block, yaw, spot)`，几何由 `SeatPlacementTest` 直接单测，不需要服务器。

> **为什么不做精确几何**：地毯只有 1/16 格高，而 26.2 没有通用的 `Carpet` 数据类
（只有 `MossyCarpet`），拿不到它的精确高度；半砖还要区分上下半。硬编码几何表正是这类插件在
版本更新时崩掉的原因，GSit、Simple Chairs 这些成熟插件都退化成「每类方块一个可配置偏移」，
本项目跟随该做法。楼梯的朝向则相反——那个 API 是有的，直接用。

## 坐下前的五道检查

每一条拒绝都有独立提示，不会静默失败：

| 检查 | 拒绝键 | 为什么 |
|---|---|---|
| 距离 | `seat-too-far` | 其他插件可能把交互距离调得远超原版 ~4.5 格，隔空放椅子会把人困住 |
| 上方净空 | `seat-blocked` | 座位正上方是实心方块，坐下去就是卡在方块里 |
| 位置占用 | `seat-taken` | 已有座位（包括**正上方**那一格）被占，一椅一人 |
| 上下颠倒 | `seat-stairs-flipped` | 台阶变成天花板，没有台面 |
| 楼梯朝向 | `seat-stairs-backwards` | 从整格面靠近，台阶在另一面 |

距离上限 `sit.max-distance` 默认 `4`，构造时强制落在 1..8 —— 配置写错会在 reload 时被拒绝，
而不是在运行时把人卡在远处。占用检查同时看座位本身和它**上面一格**，所以上下叠放的楼梯不会出现
两个人挤进同一个位置。

## 已知的实体泄漏防护

调研 CMI #6527、GSit、Simple Chairs 后，这几个坑都有对应措施：

| 坑 | 现象 | 本项目的处理 |
|---|---|---|
| 崩溃后的幽灵椅 | 盔甲架存活，玩家卡在打不破的座椅上，只能 `/kill @e` | 每个座椅打 PDC 标记，`start()` 时扫描清除 |
| 方块被破坏 | 椅子活得比方块久，人浮在坑上 | 监听 `BlockBreakEvent` 释放骑手 |
| 重复坐下 | 双重 `/sit` 生成两个座椅 | 座椅位置集合 `occupiedSeats`，一椅一人 |
| 右键冲突 | 手持物品点击被劫持，开不了箱子 | 仅空手触发，且只在真的坐下时才取消事件 |
