# 风纪委员方案（2026-10-06 讨论定稿）

本文记录 **meowo-sentinel**（风纪委员）的设计决策与分期。**尚未实现**，本文是后续动手的依据。

---

## 0. 一句话目标

一个记录玩家行为、维护每人档案、能被玩家问询，并对扰序行为发起投票裁决的服内管理角色。

---

## 1. 已确认的技术事实

这些是**在 Paper 26.2 上实际核实过的**，不是推测，改方案前请先重读这一节。

| 事实 | 影响 |
|---|---|
| **Paper 26.2 没有任何 whisper / 私聊事件**（全 jar 搜 `Whisper` / `PrivateMessage` = 0 命中） | 私聊风纪委员**必须抓包**，且**必须真人账号** |
| `io.papermc.paper.event.player.AsyncChatEvent` 存在，带 `viewers()` 接收者集合 | 聊天记录、@ 提及、风纪委员"能看到但不打断"三者都靠它 |
| Paper 无专门 @ 提及 API | @ 靠**把被提及者加进 `viewers()`** 实现，客户端自行渲染高亮 |
| `PacketEvents 2.14.0` 的 `EntityDataTypes` **无** `NAMEPLATE` / `CUSTOM_NAME` | 26.2 名牌已迁到 DataComponent，**自定义名牌不能走实体元数据发包**；改用 Paper 原生 `Nameable#customName` |
| Paper 26.2 **无** `startRiding` / `stopRiding` | 骑乘必须用 `vehicle.addPassenger(rider)`，1.21 教程全部失效 |
| `Stairs` 的 `getFacing()` / `getHalf()` **继承自** `Directional` / `Bisected` | 只 grep `Stairs.class` 会误判"API 没了"，必须 `javap -p` 并追父接口 |

> 通用教训：**验证 API 要做两件事** —— jar 里确认方法**存在**，以及在 MockBukkit 里**真的调用一次**并断言结果。只做前者会被「返回 null 不抛异常」骗过。
> 参见 [08 §6c](minimax/08-坑与反模式.md)。

## 2. 技术选型：不用 LangGraph

**LangGraph 是 Python / JS 库，没有 JVM 版。** 但更重要的是——这个场景不需要图编排。

状态机只有 5 个状态，没有分支回环、没有并行节点：

```
定时触发 → 采集行为 → 规则判定 → 落库 → （被问时）查询 + 应答
```

JVM 侧选项对比：

| 库 | 判断 |
|---|---|
| LangChain4j | 有 tool / RAG，但非 Kotlin 优先，且不是图运行时 |
| Spring AI | 有 chat memory，但本项目不用 Spring |
| **Kotlin 手写状态机** | ✅ 约 200 行，零依赖，完全可单测 |

**结论：不引入任何 LLM 框架。** 真要接大模型，定义一个 `Advisor` 端口即可，domain 层不依赖任何实现。

---

## 3. 分层：规则判定，AI 只措辞

这是本方案**最重要**的一条决策。

**判定必须自己实现，AI 只能放辅助位，且永远不能用来处罚。** 三条理由：

1. **处罚必须可申诉。** 「AI 认为你不友善」无法复核；「你在 14:32:07 触发规则 CHAT-3，原文是这句」可以。风纪委员最危险的翻车不是漏判，是判错且说不出理由。
2. **成本不匹配。** 全服聊天是 7×24 持续流，按 1% 抽样也是每天数百次调用 —— 永久账单。
3. **非确定性摧毁测试体系。** 接入后「这条消息应被标记」变成 mock 网络 + 容忍概率的断言，`domain` 纯函数 0.2 秒跑完几百用例的优势直接归零。

### 职责分配

| 层 | 做什么 | 依赖 AI |
|---|---|---|
| L1 归一化 | 去符号、全角转半角、识别拼音首字母（nmsl / sxyl）、变体字 | ❌ |
| L2 规则判定 | 命中即记录，带类别与严重度 | ❌ |
| L3 上下文豁免 | 是否引用他人 / 玩梗 / 同一句高频出现 | ❌ |
| L4 AI（可选） | **只处理 L2 判为灰区的一小撮** | ✅ 只升级为「人工复核」 |

**L1 是被严重低估的一层。** 多数人以为关键词匹配没用，其实是没做归一化：

```
n*ms*l  →  nmsl
ＮＭＳＬ  →  nmsl
nmsl    →  nmsl
```

做了归一化，朴素词表命中率大幅提升，且**完全确定性、零成本、可单测**。

### 哪些类别根本不需要 AI

| 类别 | 判定方式 |
|---|---|
| 刷屏 | 计数阈值（10 秒内 N 条） |
| 广告 / QQ 号 | 正则 |
| 直接辱骂 | 归一化 + 词表（覆盖绝大多数真实案例） |
| 死循环挑衅 | 计数 + 冷却期 |

危害最大且频率最高的类别**全是规则友好的**。AI 的边际收益只在**低频、高歧义**的反讽 / 玩梗 / 煽动上 —— 这类恰恰低频，所以只喂这一小撮，成本从「全服每条」降到「每天几十条」。

### 隐私

已在为每人建聊天档案。**若接 AI，等于把画像 + 原文一起送出。** 若最终接入：自部署，或用明确不训练、可关闭的通道，且**只送单条灰区消息，不送历史**。

## 4. 分期

| 期 | 交付 | 依赖 | 状态 |
|---|---|---|---|
| 1 | `meowo-mine`：稀有矿物首挖全局通报（MineCat） | 无 | **本次实现** |
| 2 | `meowo-chat`：聊天记录 + 格式化 + @ 提及 | 无 | 未开始（[设计预留](../contexts/meowo-chat/README.md)） |
| 3 | `meowo-sentinel`：定时巡检聊天 + 档案 + 投票 | 1,2 | 未开始 |
| 4 | 私聊接入 | 3 + 真人账号 + 抓包 | 未评估，成本最高 |

**先做 1 和 2**，因为它们完全不依赖私聊方案的决策，可以立刻交付价值。第 3 期才是风纪委员本体。

### context 划分

```
meowo-mine       挖掘统计 + 通报（本次）
meowo-chat       聊天格式化 + 记录 + @
meowo-sentinel   巡检 + 档案 + 投票（消费上面全部）
```

**统计是唯一真相来源，上层只做编排。** 这样风纪委员将来调用工具时直接查 `meowo-mine`，不重复实现计数。

## 5. 私聊：为什么放在最后一期

服务端能看到私聊内容（它负责转发），但**没有事件可拦截**。只有两条路：

| 方案 | 私聊 | 代价 |
|---|---|---|
| **A1. 改用 @ 或命令** | ❌ 非真私聊 | 零成本，先跑通全链路 |
| **A2. PacketEvents 抓包** | ✅ 需真人账号 | 要确认 2.14 在 26.2 能否解析出私聊目标与正文；**且发信也需真人账号在线** |

**假玩家收不到私聊** —— 这是协议层限制，`PacketEvents` 造的 NPC 是纯发包实体，客户端不视其为玩家，whisper 不会路由过去。

**决策：先只做 `@` / 命令（A1），第 4 期再评估是否值得上 A2。** 两者投入差一个数量级。

---

## 6. 投票的护栏（写进设计，不许删）

「按在线人数发起投票」如果没护栏，会变成**玩家互相施加惩罚**的工具。必须：

- **必须有已记录的 `incident` 才能发起投票** —— 不能凭投票凭空捏造指控
- **同一目标有冷却期**
- **最低参与人数**，且**弃权即不通过**（不是简单多数）
- **投票只能提高人工判定的处罚力度，不能凭空产生处罚**

理由不是道德，是可用性：**一个记错且无法纠正的风纪委员，会变成制造冤案的工具。** 而这类插件最常见的翻车方式正是这个。

---

## 7. 服内透明

建议开局就明示：风纪委员在记录、记录什么、保留多久、如何查看和删除自己的档案。

技术上也支持：档案表独立于 economy 钱包库，**可整表清空、可按人删除、可设保留期**。
