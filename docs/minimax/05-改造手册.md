### ⑤ 实现 `Context`

```kotlin
class ChatContext(private val host: PlatformHost) : Context {
    override val id = "chat"                      // 必须与配置开关名一致
    private val active = AtomicBoolean(false)
    private val resources = mutableListOf<AutoCloseable>()

    override fun start() {
        active.set(true)
        Bukkit.getPluginManager().registerEvents(this, host.plugin)
        resources += AutoCloseable { HandlerList.unregisterAll(this) }
        resources += host.commands.register("chat", object : Route { ... })
        resources += host.events.subscribe(SomeEvent::class.java) { ... }
    }

    override fun close() {
        active.set(false)
        resources.asReversed().forEach { it.close() }; resources.clear()
    }
}
```

契约见 [02 §4](02-运行时与生命周期.md)。`close()` 必须幂等。

### ⑥ `MeowoRuntime.applySettings` — 三处

```kotlin
// 1) 停用分支（按依赖逆序插入）
if ("chat" in next.contexts && !contexts.isEnabled("chat")) contexts.enable(ChatContext(host))

// 2) 条件重启分支（若 chat 受某些配置影响）
if (settings?.chatOption != next.chatOption) contexts.disable("chat")

// 3) 启用顺序：放在最后，依赖先于它
if ("economy" in next.contexts && !contexts.isEnabled("economy")) contexts.enable(EconomyContext(host) { economyPolicy })

if ("teleport" in next.contexts && contexts.isEnabled("economy") && !contexts.isEnabled("teleport")) contexts.enable(TeleportContext(host, next.teleport))
if ("spawn" in next.contexts && !contexts.isEnabled("spawn")) contexts.enable(SpawnContext(host, next.spawn))
if ("chat" in next.contexts && !contexts.isEnabled("chat")) contexts.enable(ChatContext(host))
```

**同时检查 reload 成功判定**（`MeowoRuntime.kt:45`）：

## 2. 给 `eco` 加一个子动作

例：新增 `/meowo eco stats <玩家>`。

**① `contexts/meowo-economy/.../interfaces/EconomyCommand.kt`**

```kotlin
private val actions = listOf("balance", "pay", "daily", "treasury", "give", "take", "set", "stats")
//                                                     ↑ 加进列表，否则直接回 eco-usage
```

权限是**自动**的：`if (action != "balance" && !sender.hasPermission("meowo.economy.$action"))`。
`complete()` 里的 `actions.filter { ... }` 也自动生效，不用改。

**② 参数数量校验**（该文件里每个分支各自判断 `args.size`）：

```kotlin
if (action == "daily" || action == "treasury") { if (args.size != 1) { ...; return } ... }
if ((action == "balance" && args.size > 2) || (action != "balance" && args.size != 3)) { ...; return }
```

**新动作若不是「无参」也不是「目标+金额」，要在中间加一条独立判断**，别混进上面两条。

**③ `plugin.yml` 权限**：

```yaml
meowo.economy.stats:
  default: op
  # 若希望 meowo.admin / meowo.economy.* 自动包含，还要加 children
```

`meowo.economy.*` 是显式 children 列表——**加进 `meowo.economy.*: children:` 下面**，
否则 OP 之外拿到 `meowo.economy.*` 的组不会自动获得它。

**④ 语言键**：`eco-usage` 文案要同步更新（两个语言文件），否则提示里看不到新动作。

**⑤ 测试**：`MeowoRuntimeTest` 加一个 `@Test`，用
`server.dispatchCommand(server.consoleSender, "meowo eco stats Steve")` + `balance(...)` 辅助方法。

## 3. 新增一个顶层命令（如 `/meowo shop`）

不要新开 Bukkit 命令，直接**在 router 里注册一个子路由**：

```kotlin
// context 的 start() 内
resources += host.commands.register("shop", object : Route {
    override val permission = "meowo.shop"
    override fun execute(sender: CommandSender, args: List<String>) { ... }
    override fun complete(sender: CommandSender, args: List<String>): List<String> = ...
})
```

`MeowoRuntime.applySettings` 会自动把它纳入 reload 生命周期。
`/meowo help` 的文案在 `lang/*.yml` 的 `help` 键里，记得同步。

**只有需要独立命令名/独立参数语法时**（像 `/pay`、`/tpa`）才改 `plugin.yml` 的 `commands`
并在 `MeowoRuntime` 的 `aliases` map 里加前缀映射（`MeowoRuntime.kt:30-31`）：

```kotlin
private val aliases = mapOf("pay" to listOf("eco", "pay"), "tpa" to listOf("tpa"),
    "tpaccept" to listOf("tpa", "accept"), ...)
```

机制：`/pay Receiver 2.50` → 拼成 `["eco","pay","Receiver","2.50"]` → 同一个 router。
所以 `plugin.yml` 里的 `usage` 只是给客户端看的，不影响实际解析。

## 4. 新增 / 修改一条文案

**两个语言文件都要改，键名一致**。当前 47 个键，`zh_CN.yml` 与 `en_US.yml` 键集合与占位符集合完全对齐
（改完可用 `comm` 对账）。

### 消息能力（Paper 26.2 已验证）

| 能力 | 支持方式 | 说明 |
|---|---|---|
| 传统颜色 | `§` + `0-9a-fk-or` | **仅玩家**渲染；`Messages.send` 对非玩家自动去除 |
| 聊天发言者 | `ChatLine.say(name, body)` 自己拼前缀 | 玩家看到 `✉ EconCat 消息`；**仅玩家**，控制台无发言者。<br>⚠️ 不要改回 `ChatType.CHAT.bind`——`<>` 由客户端画，删不掉，见 [09 §2](09-模拟玩家发言可行性.md) |
| 多行 | YAML 块标量 `|-` + `\n` | 玩家收到**一条**消息、内含换行；控制台按行拆分 |
| 占位符 | `{0}` `{1}` | 按 `text(key, vararg args)` 顺序替换；**不用** `%s` |

颜色码是 **Paper 原生**：`CraftPlayer.sendMessage` → `sendRawMessage` →
`CraftChatMessage.fromString` 返回 `Component[]`（按 `\n` 切分、解析 `§` 码）后逐条发送。

### 发言者（`XxxCat`，Xxx 恰好 4 字符）

所有玩家可见的聊天消息都会归属到一只猫，**新增 context 时不需要改任何发送代码**：

| id | 默认名 | 负责 |
|---|---|---|
| `system` | `MeowCat` | `info` `help` `reload-*` `no-permission` `unknown-*` `player-only` `internal-error` |
| `economy` | `EconCat` | `eco-*` `error-*` `balance` `treasury` `daily-*` `pay-*` |
| `menu` | `MenuCat` | `menu-*` `unavailable`（目前都是物品名 / 库存标题，**不走聊天**） |
| `render` | `RendCat` | `render-*` |
| `spawn` | `WarpCat` | `spawn-*` |
| `teleport` | `TeleCat` | `tpa-*` `action-*` |

**命名规则：`XxxCat`，`Xxx` 恰好 4 个字符**——所有发言者在聊天栏里等宽对齐。
`render` 直接截断成 `Rend`；`spawn` **不截断**（`Spaw` 不可读），改用项目内既有说法
「回城」→ `Home`。
`UnknownCat` 是 7 字符的兜底名，只在 id 完全无映射时出现，正常路径看不到。

解析顺序在 `Messages` 里：**精确键 → 键前缀 → `system`**。

**新增 context 或新键时：**

1. 先看键的前缀是否已被某个 `SPEAKER_PREFIXES` 覆盖；没有就在 `SPEAKER_KEYS` 加精确映射。
2. 忘了加也不会崩——会落到 `MeowCat`，但**归属会错**，所以记得同步。
3. 改名只需改语言文件的 `speaker-<id>`；留空或删掉则回落到代码默认值，
   未知 id 回落 `UnknownCat`，**绝不会把原始键名发给玩家**。

### 约定

```yaml
# 语法：|- 块标量写多行；颜色语义固定
no-permission: "§c✖ §f你没有权限执行该操作。§r"        # 错误：§c + ✖
balance:      "§7» §f{0} §8· §7余额 §e{1}§r"          # 查询：§7» + 数值 §e
render-limit: |-                                        # 错误 + 指引
  §c✖ §f数量无效，或将超过个人上限 §e{0}§f。
  §7» §7已生成的数量同样计入上限。
help: |-                                                # 结构化多行
  §b§lMeowo §8· §7命令帮助
  §8────────────────────────────────
  §7▸ §f/meowo info §8— §7查看版本与实际启用的模块
```

> 玩家收到的是**一条**消息（`\n` 保留在内容里），所以只出现一次发言者前缀；
> 控制台没有发言者，会按 `\n` 拆成多行。**客户端是否把消息内的 `\n` 渲染成换行尚未实机验证**，
> 见 [09 §5](09-模拟玩家发言可行性.md)。

| 语义 | 颜色 | 符号 |
|---|---|---|
| 成功 | `§a` | `✔` |
| 错误 | `§c` | `✖` |
| 提示/警告 | `§e` `§7` | `⚠` `»` `▸` |
| 数值强调 | `§e` | — |
| 品牌 | `§b` | — |
| 弱化/分隔 | `§8` | `─` `│` `—` |

### 硬性规则

- **占位符数量必须与调用点一致。** 没传的 `{0}` 会**原样显示**（`text()` 只替换已提供的参数）。
  新增键前先确认 `messages.send(...)` 到底传了几个参数。
- **颜色只是修饰。** 管理员可以编辑 `plugins/Meowo/lang/*.yml` 写成纯文本，功能不受影响。
  所以**不要**把语义只放在颜色里。
- **非字符串值会拒绝整包重载**（`require(!config.contains(key) || config.isString(key))`），
  保留旧文案。写 `key: 123` 会导致 `/meowo reload` 报 `reload-failed`。
- **控制台不渲染颜色**，所以文案要在去掉 `§` 后依然可读——不要写成
  `§c余额不足§r（§7code=INSUFFICIENT_FUNDS§r）` 这种把信息藏在颜色里的形式。

### 可点击操作（Adventure 组件）

`platform/Messages.kt` 提供三个方法，把语言键渲染成带点击/悬停的组件：

```kotlin
fun component(key: String, vararg args: Any): Component            // 保留 § 颜色
fun action(labelKey: String, command: String, hoverKey: String? = null, vararg args: Any): Component
fun actionLine(vararg actions: Component): Component                 // 用 action-separator 连接
fun send(sender: CommandSender, message: Component)
```

约定：

- **命令由代码提供，绝不来自语言文件。** 点击以**点击者**身份执行，权限校验照常生效。
- 命令必须以 `/` 开头（`ClickEvent.runCommand`）。
- 行首前缀与分隔符是两个共享键：`action-prefix`（`§7» `）、`action-separator`（` §8· `）。
- 非玩家收到组件时会退化为**无色纯文本**（`PlainTextComponentSerializer`），因为点击对控制台无意义。

teleport 的用法（`TeleportContext.sendActions`）：

```kotlin
host.messages.send(target, host.messages.component("action-prefix").append(
    host.messages.actionLine(
        host.messages.action("tpa-click-accept", "/tpaccept $other", "tpa-click-accept-hint", other),
        host.messages.action("tpa-click-deny",   "/tpdeny $other",   "tpa-click-deny-hint",   other),
    )))
```

> Adventure 来自 **paper-api（`compileOnly`）**，不要显式加依赖，也不要打进 jar。
> 现有 10 个点击相关键：`action-prefix`、`action-separator`、
> `tpa-click-{accept,deny,sponsor,refuse}` 及其 `-hint`。

### help 必须按权限过滤

**`/meowo help` 曾经是一整块静态文案**，所以它把 `/afk`、`/reload`、经济管理指令
**一并展示给所有人**——哪怕补全框早就按权限过滤了。两者自相矛盾。

现在 help 由 `platform/HelpPage` 组装：文案仍在语言文件里，只有**过滤**在代码里。

```yaml
help-header: |-     # 横幅
help-line: "§7▸ §f{0}"   # 单行模板
help-footer: |-     # 结尾提示
help-commands: |-    # 每行「路由名|显示文案」
  info|§7查看版本与实际启用的模块
  afk|§7手动标记离开
```

```kotlin
// CommandRouter：help 与补全共用同一套判断
fun isVisible(sender: CommandSender, name: String) =
    routes[name]?.let { sender.hasPermission(it.permission) } ?: false
```

**两条硬规则**：

1. **未知路由要显示，不要隐藏。** 语言文件里写错名字时，宁可多显示一行，
   也不要让一条命令**静默消失**——后者没人会发现。
2. **必须走 `Messages.sendText`，不要直接 `sendMessage`。** 否则控制台会看到
   裸的 `§` 颜色码（`sendText` 才是去色 + 按行拆分的那个入口）。

## 5. 新增一个 `EconomyError` 错误码 ⚠️

**最容易被漏的配方。** `api/EconomyAPI.kt`：

```kotlin
enum class EconomyError { INVALID_AMOUNT, INSUFFICIENT_FUNDS, LIMIT_EXCEEDED,
    SELF_TRANSFER, TRANSFER_PENDING, UNAVAILABLE, /* 新增 */ MY_NEW_ERROR }
```

`PlatformHost.reply` 会拼出键名 `"error-${code.name.lowercase()}"`，例如
`MY_NEW_ERROR` → `error-my_new_error`。**这个键不存在时，玩家会直接看到
`error-my_new_error` 这串原始文本**（`Messages.text` 返回键本身），而且**不会报错**。

所以必须：

- [ ] `lang/zh_CN.yml` 加 `error-my_new_error: "中文提示"`
- [ ] `lang/en_US.yml` 加 `error-my_new_error: "English message"`
- [ ] 若是非 `EconomyException` 路径，确认走的是 `internal-error`

自查：

```bash
grep -o 'error-[a-z_]*' core/src/main/resources/lang/*.yml | sort -u   # 与枚举值对账
```

现有 6 个键：`error-invalid_amount`、`error-insufficient_funds`、`error-limit_exceeded`、
`error-self_transfer`、`error-transfer_pending`、`error-unavailable`。

## 7. 暴露新的跨 context 能力

**先问：真的需要吗？** `MenuContext` 只经 `EconomyAPI` 就够了，不需要更多接口。
chat README 也明确「无实际需求时无需增加 API」。

确需时：
1. `api/` 定义接口，**签名只用 `UUID` / `String` / `BigDecimal` / `CompletionStage`**
2. 实现类在所属 context 的 `start()` 里 `ServicesManager.register`
3. `resources` 里加精确 `unregister(接口, 那个实例)`
4. 使用方 `Bukkit.getServicesManager().load(X::class.java) ?: error("context is disabled")`

**调用方必须每次重新 `load`**，不能缓存——重载后旧引用会返回 `UNAVAILABLE`。

## 10. 调整传送税 / 每日补助

**改默认值**：`core/src/main/resources/config.yml` + `GlobalConfig` 里的 `decimal("...", 默认)`。
两处都要改——config.yml 是新安装的模板，`GlobalConfig` 的第二参数是旧配置缺项时的回落。

**新增配置项要 +1 版本号**：改 `ConfigVersionMerger.CURRENT_VERSION`，
否则服主的 `config.yml` 里永远不会出现这个新键（`saveDefaultConfig` 只在文件缺失时写）。
启动时合并器会把缺的键连同注释补进去，**已有的键一律不动**。详见 [ui-style.md](../ui-style.md#配置文件版本)。

> ⚠️ 合并器**只加不删**。删掉一个配置项不会从服主文件里移除，只会停止补新键——
> 这是刻意的，见 `ConfigVersionMerger` 的类注释。

**验证**：`EconomyPolicyTest`（3 个测试）覆盖费用计算；`MeowoRuntimeTest` 的
`invalid tax currency and timezone reloads preserve the active policy` 覆盖非法配置不生效。

`rate` 是**小数比例**（`0.001` = 0.1%），`init` 里 `require(rate >= 0 && rate <= 1)`。

## 11. 调整渲染上限

`render.max-per-player`（1..1000）需要**三处**一致：

| 位置 | 内容 |
|---|---|
| `core/src/main/resources/config.yml` | `max-per-player: 200` |
| `core/.../config/GlobalConfig.kt` | `integer("render.max-per-player", 200)` + `require(limit in 1..1000)` |
| `render/.../application/RenderService.kt` | `init { require(maxPerPlayer in 1..1000) }` |

上限变化会**触发 render 停用重启**（`applySettings` 里的 `renderLimit` 比较），
测试要覆盖「改 limit 后旧实体被清理、新 limit 生效」。
