## 2. JDK 矩阵的实际机制

`build.gradle.kts:15-25`：

```kotlin
extensions.configure<KotlinJvmProjectExtension> {
    jvmToolchain(25)                                  // 编译与测试用 JDK 25
    compilerOptions.jvmTarget.set(JvmTarget.JVM_21)   // 但产物字节码目标是 21
}
extensions.configure<JavaPluginExtension> {
    sourceCompatibility = JavaVersion.VERSION_21
    targetCompatibility = JavaVersion.VERSION_21
}
configurations.configureEach {
    if (isCanBeResolved) attributes.attribute(TargetJvmVersion.TARGET_JVM_VERSION_ATTRIBUTE, 25)
}
```

**含义**：
- 代码用 **JDK 25** 的编译器/API 编译，可以写 Java 21+ 才有的 API。
- 但产出字节码标记为 **Java 21**，因为 Bukkit 服务端加载器按 21 解析插件类。
- 依赖解析也按 25 校验，避免拉到低字节码的变体。

### daemon 用哪个 JDK：这是**硬约束**，不是可选项

> **2026-10-30 更正。** 这一节原来写着「daemon 用 21 没有被配置固定，把 daemon 固定到 21 属于可选
> 优化，不是构建前提」。**那句话是错的。**
>
> `gradle/gradle-daemon-jvm.properties` 确实存在且已提交：
>
> ```properties
> # Gradle 8 runs on Java 21; compile/test/server use the Java 25 toolchain.
> toolchainVersion=21
> ```
>
> 实测（2026-10-30）：机器上只有 JDK 25 可被发现时，构建**直接失败**——
>
> ```
> Cannot find a Java installation on your machine (Mac OS X 27.2 aarch64) matching:
> {languageVersion=21, vendor=any vendor, implementation=vendor-specific, nativeImageCapable=false}.
> Toolchain auto-provisioning is not enabled.
> ```
>
> 那个文件里的 `toolchainVersion=21` 就是 daemon 的准入条件，而 `settings.gradle.kts` **没有配
> foojay resolver**，所以 Gradle 不会去下载 JDK 21——它只会告诉你「找不到」。构建能否进行，取决于
> 机器上有没有一个 JDK 21。
>
> 还有一个更硬的边界：**Gradle 8.14 的 daemon 跑不了 JDK 25。** 实测把那个文件删掉、让 daemon 直接
> 用 25，构建报的是一句没有主语的 `25.0.2`（Gradle 解析不了这个版本号）。所以「daemon 21 +编译 25」
> 不是偏好，是这套版本组合下唯一可行的形状。
>
> **CI 因此必须装两个 JDK。** `.github/workflows/ci.yml` 与 `release.yml` 都装 21 和 25，
> 并用 `-Dorg.gradle.java.installations.paths="$JDK21,$JDK25"` 把两个位置都告诉 Gradle——
> `setup-java` 把它们装在不同目录，而 Gradle 不会自己去那儿找。
>
> **本机也是同一件事。** 下面写的「PATH 上的默认 java 是 17」不再重要：daemon 用的是准则里写的 21，
> 而 Gradle 自动发现能找到 `azul-21.0.7`。构建之所以在本机跑得通，是因为这台机器**恰好**装了 21。

### 本机实际情况（已核实）

```
$ java -version
openjdk version "17.0.9" 2026-04-15      ← PATH 上的默认 java 是 17

$ /usr/libexec/java_home -V
25.0.2  graalvm-ce-25.0.2     ← toolchain 实际用这个
23.0.2  openjdk-23.0.2
21.0.7  azul-21.0.7 / graalvm-jdk-21.0.7
17.0.15 ms-17.0.15 / azul-17.0.15
```

- `~/.gradle/gradle.properties` **不存在**，没有 `org.gradle.java.installations.paths`。
- 因此 **Gradle 靠自动发现**（日志里的 "Daemon JVM discovery is an incubating feature"）
  找到 graalvm-ce-25.0.2 供 toolchain 使用，找到 azul-21.0.7 供 daemon 使用。
- 失败栈里出现过 `java.base@25.0.2/...`，**证实测试 JVM 确实是 25**。

**自动发现找不到时**（比如换台只有 25 的机器），显式指路：

```bash
./gradlew -Dorg.gradle.java.installations.paths="$JDK21,$JDK25" ...
```

或者写进 `~/.gradle/gradle.properties`：

```properties
org.gradle.java.installations.paths=/path/to/jdk21,/path/to/jdk25
```

## 3. 常用命令

```bash
# 完整验证（推荐，每次改动后）
./gradlew test :core:build verifyArchitecture verifyCoverage --no-daemon

# 只跑单元测试（快）
./gradlew test

# 只跑架构检查
./gradlew verifyArchitecture

# 只打包
./gradlew :core:build

# 单模块测试
./gradlew :contexts:meowo-economy:domain:test      # 纯 JUnit，~0.2s
./gradlew :shared:test

# 清理（iCloud 环境下几乎必做，见 08 §1）
./gradlew clean
```

**先 `clean` 再验证**。本项目位于 iCloud Drive，重复的 `.class` 文件会残留（[08 §1](08-坑与反模式.md)）。

`:core:build` 产出单 jar：`core/build/libs/Meowo-1.0.0.jar`
（`archiveBaseName` 在 `core/build.gradle.kts:27` 设置为 `Meowo`）。

## 4. 本地服与客户端

### 启动服务端

```bash
ACCEPT_MINECRAFT_EULA=true ./scripts/start-server.sh
# 或
ACCEPT_MINECRAFT_EULA=true ./gradlew :core:runServer      # 已 --skip-build
```

`start-server.sh` 做的事：
1. **检查 Java 版本**，不是 25 就退出并提示 `MEOWO_JAVA`
2. 除非 `--skip-build`，先跑 `:core:build`
3. 下载 Paper jar 和 PacketEvents jar，**逐个校验 SHA-256**（用 `python3`）
4. 复制 `Meowo-1.0.0.jar` 到 `plugins/Meowo.jar`
5. 检查 `eula.txt`，没有 `eula=true` 就拒绝启动
6. `cd .run/server && exec $JAVA_BIN -jar paper.jar --nogui`

**依赖**：`bash`、`curl`、`python3`。

### 脚本环境变量

| 变量 | 作用 | 本机值 |
|---|---|---|
| `MEOWO_JAVA` | Java 25 路径 | 由环境变量提供；未设置时用 `PATH` 上的 `java` |
| `MEOWO_RUN_DIR` | 服务端目录 | 默认 `.run/server` |
| `MEOWO_CLIENT_INSTANCE` | Prism 实例 ID | 需手动设置 |
| `MEOWO_CLIENT_LAUNCHER` | 启动器路径 | 默认 `prismlauncher` |
| `ACCEPT_MINECRAFT_EULA` | 接受 EULA | 首次需设 `true` |

> ⚠️ **`MEOWO_JAVA` 刻意不写在 `scripts/versions.env` 里。**
> 该文件会被 `start-server.sh` 读取，在里面赋值会**覆盖**操作者自己设的环境变量——想固定 JDK 25，
> 就把它设在环境里：
>
> ```bash
> export MEOWO_JAVA="$HOME/Library/Java/JavaVirtualMachines/graalvm-ce-25.0.2/Contents/Home"
> ```
>
> 不设也能跑：脚本会退回 `PATH` 上的 `java`，但那就要求那正好是 Java 25。

### 客户端联调

```bash
MEOWO_CLIENT_INSTANCE='你的实例 ID' ./scripts/start-client.sh
MEOWO_CLIENT_INSTANCE='你的实例 ID' ACCEPT_MINECRAFT_EULA=true ./scripts/dev.sh   # 双开
```

`dev.sh`：在后台轮询 `/dev/tcp/127.0.0.1/25565`，端口就绪才启动客户端；服务端留在前台。
最多等 300 秒。

**客户端不下载也不绕过正版认证**——必须先用 Prism 建好 **26.2 / Java 25** 实例并登录正版账号。
未配置 `MEOWO_CLIENT_INSTANCE` 会**明确报错**，不会假装启动成功。

### 测试服配置

`scripts/server.properties`：**仅本机开发用**，只监听 `127.0.0.1:25565`、离线模式。

`level-type=minecraft:flat` **必须带 `generator-settings`**（layers + biome）。
第一次建服时缺少它导致 Paper 报错，已在 `scripts/server.properties` 补齐。
**新建 `MEOWO_RUN_DIR` 时记得复制这个文件**，否则超平坦生成会失败。

停止：在服务器控制台输入 `stop`。

## 5. TabooLib 首次运行

TabooLib 会在**首次启动时下载自身运行时模块**，需要访问 Maven Central 和 TabooLib 仓库。
**离线部署必须预先准备 `libraries/` 缓存**（`.run/server/libraries`）。

`core/build.gradle.kts` 的 taboolib 配置：

```kotlin
env { install(Basic, Bukkit) }
version { taboolib = ...; skipKotlinRelocate = true; coroutines = null }
```

`skipKotlinRelocate = true` —— **Kotlin 标准库不重定位**，避免与 Bukkit 生态里其他插件的
Kotlin 版本冲突。这也意味着**不能依赖重定位隔离 Kotlin 版本**。

## 6. 模块与依赖

```
api            公开契约（无依赖）
shared         EventBus / ContextManager（仅 kotlin-stdlib）
platform       命令路由、语言包、主线程切换   → api、shared
contexts/meowo-economy/domain   纯领域        → api
contexts/meowo-economy          编排 + SQLite → domain、platform、shared、sqlite
contexts/meowo-menu                           → platform、api、shared
contexts/meowo-render                         → platform、api、shared、packetevents(compileOnly)
contexts/meowo-teleport                       → platform、api、shared
contexts/meowo-spawn                          → platform、api、shared
core            唯一入口 + 组合根               → 全部（TabooLib 打包）
```

`api` 和 `shared` 的 `build.gradle.kts` 只有注释、**零依赖**——这是它们"纯净"的物理保证。

**Paper 与 PacketEvents 一律 `compileOnly`**（真实由服务端提供）。
测试用 `testImplementation` 同时引入 `mockbukkit` 和 `paper.api`。

`platform` 用 `api(project(":api"))`（不是 `implementation`），
所以依赖 platform 的 context 能直接看到 `api` 类型。

## 7. `plugin.yml` 关键点

`core/src/main/resources/plugin.yml`：

- `version: '${version}'` —— 由 `core/build.gradle.kts:25` 的 `processResources` 展开
- `api-version: '26.2'`
- `main: com.meowo.taboolib.platform.BukkitPlugin` —— TabooLib 生成的桥接类，**不是** `MeowoCore`
- `softdepend: [packetevents]` —— 缺失只影响 render
- 权限树显式声明 `meowo.economy.*` 的 children（见 [05 §9](05-改造手册.md)）

## 8. 产物

单 jar fat jar，含：全部 context、TabooLib 引导、Kotlin 标准库、SQLite JDBC。

```bash
unzip -l core/build/libs/Meowo-1.0.0.jar | grep -cE '\.class$'     # 类数量
unzip -l core/build/libs/Meowo-1.0.0.jar | grep -E 'com/meowo/(contexts|teleport|menu|render)' | head
shasum -a 256 core/build/libs/Meowo-1.0.0.jar
```

部署：把 jar 复制到 Paper 的 `plugins/`。渲染功能另需 PacketEvents 2.14.0。

**本项目不是 git 仓库**（根目录无 `.git`），`.gitignore` 只是为将来预留的规则文件。
需要版本管理时先 `git init`，否则没有 diff / 回滚能力。
