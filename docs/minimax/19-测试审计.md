# 19 · 测试审计（2026-10-25）

---

## 1. 这份文档是什么

一次对**全部测试代码**的审计：120 个测试文件、1425 个测试（审计前），逐个对照 `src/main` 判定它们到底守住了什么。

> **审计后的基线**：1430 个测试，0 failure / 0 error / **0 skipped**（128 个测试类）；总体行覆盖率 **83.46%**，economy domain **94.74%**。`./gradlew check` 全绿。

目的只有一个：**找出给人假信心的测试**。覆盖率高不等于测试有效——一条恒真断言、一份手写镜像、一个提前 `return`，都能让构建全绿而真正的风险没人看着。

审计的标准取自本目录自己的红线：[06-测试与验证](06-测试与验证.md)（分层、命名、`skipped` 必须为 0）与 [08-坑与反模式](08-坑与反模式.md)（镜像漂移、断言断在错误的层、MockBukkit 静默降级）。

## 2. 什么叫「垃圾测试」

本次只认四类，每一类都能说清「什么输入 → 生产是错的 → 测试还是绿的」：

| 类 | 形状 | 本次实例 |
|---|---|---|
| **A 断在错误的层** | 断言的是中间表示，不是系统真正对外的值 | `ImpressionServiceTest` 断言消息条数，却叫「offers no tools」 |
| **B 断言替身** | 测的是测试自己的 fake / 镜像，而不是生产代码 | `MineVeinTest` 自己重写了一遍矿脉扫描，从不调用生产代码 |
| **C 恒真** | 在类型上或字面上就不可能失败 | `used.size == used.count()`（Set 上恒等） |
| **D 守错对象** | 测试存在且通过，但没走到真正有风险的那条分支 | `TravelJournalTest` 的坐标比较从未执行 |

这四类的共同点是：**测试绿了，而你以为它守住了某样东西。**

## 4. 顺带挖出来的 5 个真实 bug

这些不是测试的问题，是测试**本该**抓住、却因为镜像漂移而没抓住的东西。

### 4.1 番茄钟的所有消息都被系统猫冒名

两个语言包都写着 `speaker-pomodoro: "PomoCat"`，但 `Messages.SPEAKER_PREFIXES` 里没有 `pomodoro-` 前缀，`DEFAULT_SPEAKERS` 里也没有 `pomodoro`。于是 `speakerOf("pomodoro-started")` 落到兜底的 `"system"`——**番茄钟的每一句话都由 "MeowCat" 署名，语言包里那只猫永远选不出来**。

`ownerOf` 镜像的 `else -> "system"` 与生产一致，所以那条测试不可能发现它。

### 4.2 商店猫的名字没法被服主覆盖

`DEFAULT_SPEAKERS` 有 `shop`，但两个语言包都**没有 `speaker-shop`**。`Messages.readBundle` 是按 jar 里那份语言包的键去遍历的，所以服主自己写的 `speaker-shop` 永远不会被读到——商店猫的名字改不了。而且 `speaker-summary-shop` 同样缺失，`/meowo who` 里这只猫的简介显示的是**裸键**。

### 4.3 预设满额时改不了自己的预设

`SqlitePresetRepository.save` 的限额判断是 `COUNT(*) < limit`，**不区分新增还是更新**。玩家已有 3 个自定义预设（上限 3），在编辑器里改其中一个的名字 → `COUNT(*)` 是 3 → `3 < 3` 为假 → 抛「preset limit reached」，玩家被告知「达到上限」。

上限的语义是「玩家能**拥有**几个」，改名不改变拥有数。假仓储写的是 `existing || owned < limit`，说明作者原本就是这么想的——**漂移的是生产侧**。

### 4.4 `MineContext.veinSize` 是死代码

私有函数，全仓零调用点。而 `MineVeinTest` 镜像的正是它。已删。

### 4.5 三只猫的宽度不满足命名规则

`Messages` 的规则是「4 个字符 + `Cat`」，理由是**聊天栏要能对齐**。但 `SitCat`、`HatCat`、`InvCat` 只有 6 个字符——`sit` 和 `hat` 没有四个字的同义词，`invsee` 也没有更短的。

旧测试只断言了 6 个 id（system / economy / menu / render / spawn / teleport），**恰好这 6 个都合规**，所以三只宽度不对的猫一直没人看。现在测试覆盖全部 15 个 id，三个例外被显式写在测试里——这样**新增**一只不合规的猫仍会让测试红。

要不要把这三只猫改名（比如给 invsee 换成 `BagCat`）是玩家可见的取舍，不该由一次测试审计替它定。

## 5. 没修的一条，因为它是产品决定

**委派机制在生产路径上不存在。** `Guard.nextDelegate`、`CatRegistry.resolveChain`、`CatTurn.Delegate` 三个东西**只有测试在调**；`AgentRuntime` 和 `AgentsContext` 各有一个 `is CatTurn.Delegate ->` 分支在处理一个永远不会出现的值。6 个绿测试让人以为「猫之间的转手有 2 层上限、不会成环」被强制执行，实际上生产路径里根本没有转手机制——委派完全是提示词里的一句散文。

要么**接线**（让模型能返回 `CatTurn.Delegate`，用 `nextDelegate` + `resolveChain` 真正执行深度上限与防环，再补一条端到端测试），要么**删掉**（连同 `AgentRuntime.MAX_DELEGATIONS` 这份常量镜像和那 6 个测试方法）。这是产品语义的选择，不该由一次测试审计替它做。

## 6. 还欠着的

### 建议修（有风险却没测试）

- **坏过滤词不许拖垮整个聊天 context**：`RuleSet.fromConfig` 的 catch 块 0 覆盖。运维在 `config.yml` 里写错一个正则 → 整个聊天 context 起不来。
- **队列满了必须变成 failed future，绝不能挂住**：`ChatLogStore` 的 `RejectedExecutionHandler` 分支 0 覆盖，运维可见的 `dropped` 计数全仓零断言。

- **`EconomyPolicy.paymentRate` 的下界**：`require(paymentRate >= 0 && <= 1)` 的前半段未覆盖，配成负数要到第一笔 `/pay` 才炸。

## 7. 本机环境：`check` 跑不起来

这不是代码问题，是这台机器的沙箱：

- `/tmp` **不可写**。`UILoaderTest` 用 `File.createTempFile`，TabooLib 的打包任务也往临时目录解包 → 两者都报 `IOException: Operation not permitted`。
- 解法（本次用到的）：`JAVA_TOOL_OPTIONS="-Djava.io.tmpdir=$PWD/.tmp"`。必须用 `JAVA_TOOL_OPTIONS`，因为 `-Djava.io.tmpdir=…` 只作用于 Gradle 自己的 JVM，**不会传给 fork 出去的测试 JVM**。
- 顺带：`.tmp/` 里堆着 **16 个 TabooLib 泄漏的临时 jar**（约 50MB），是那些失败任务解包后删不掉的残留。已清理。
- Kotlin 编译守护进程连不上（`~/Library/Application Support/kotlin/daemon/` 不可写），会回落到进程内编译——只是慢，不是错误。

## 8. 两条给自己的提醒

1. **镜像实现必须和被镜像的代码一起改。** 本次 14 条必修里有 **5 条**是镜像漂移（`ownerOf`、`connected()`、`FakePresetRepository`、`CallBudget` 的切分公式、`ProfileText` 的数字规则）。每一份副本都是一个等着被接上的第二个答案。
2. **断言要落在系统真正对外的值上。** 「断言中间表示」「断言 fake 的记账」「断言目录而不是持有者」这三种写法，产生的都是绿色的、什么都不证明的测试。
