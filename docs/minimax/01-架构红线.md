# 01 · 架构红线

9 条**不可违反**的约束。每条给出：规则 → 为什么 → 谁强制它 → 违反后果。

这里的「强制」分三类：编译期（Gradle 依赖）、构建期（`verifyArchitecture` / `verifyCoverage`）、测试期（JUnit 断言）。

---

## 1. 纯模块不得引用平台 API

**规则**：`api/`、`shared/`、`contexts/meowo-{economy,chat,agents}/domain/` 的 `src/main` 下
不得出现 `import org.bukkit.*` / `import io.papermc.*` / `import taboolib.*` /
`import net.kyori.*`。

**为什么**：领域层一旦能拿到 `Player`、`Bukkit`、调度器，就可以直接把业务逻辑写进 tick 线程，
整个异步 + 事务模型就失效了。这是 DDD 在本项目里唯一的、真正带来收益的地方——domain 测试
0.2 秒跑完，不需要 MockBukkit。

**为什么连 Adventure 一起禁**：它决定的是**谁有资格产出「已渲染的组件」**。
chat 的 domain 之所以输出 BBCode（`[b]…[/b]`）而不是 `Component`，
正是因为它拿不到 Adventure —— markup 保持成纯字符串，
`ChatLine.body` 才能是全插件唯一解释它的地方，玩家的 `§` 也就永远不会被当成颜色码。

**这条曾经只有文档、没有门禁**：`15-chat.md` §2 写着「领域层连 Adventure 也不能碰」，
而 `verifyArchitecture` 当时只查 bukkit / papermc / taboolib。
**规则读起来像被强制、实际没被强制，比没有规则更糟**（见 [08 §44](08-坑与反模式.md)）。
2026-10-08 补进 `build.gradle.kts:57`，并实测过它会拦：

```
pure source root must not depend on the platform: import net\.kyori.* in .../GateProbe.kt
```

**谁强制**：`build.gradle.kts:42-67` 的 `verifyArchitecture`，用一份 `forbidden` 列表正则扫描
这五个目录的 `**/*.kt`，报错时点名是哪一个包名。

**自查**：

```bash
./gradlew verifyArchitecture
```

**注意扫描范围**：
- 只扫 `src/main`，**不扫 `src/test`**。测试里可以自由用 Bukkit/MockBukkit/Adventure。
- 硬编码目录列表。新增纯模块必须手动加进 `build.gradle.kts:42` 的 `pure` 列表，否则**不会被检查**——
  这是个静默漏检，见 [08 §6](08-坑与反模式.md)。

## 2. context 之间不得直接导入实现

**规则**：任何 `contexts/meowo-*/src/main` 不得 `import com.meowo.<其他 context>.`。
跨 context 只允许通过 `api/` 里的接口和事件。

受检查的 context 清单是 `build.gradle.kts:70` 的 `contexts` 列表——**本文件不复制它**，
新增 context 时去看那一份（抄两份就多一条漂移路径，见 [08 §6](08-坑与反模式.md)）。

**为什么**：这是「限界上下文」的全部意义。teleport 直接调 `EconomyApplicationService.submit`
就等于和 economy 的内部编排、线程模型、关闭时序永久耦合；economy 换个实现就得改 teleport。

**谁强制**：`build.gradle.kts:70-77`（同一个人工维护的列表，见上条警告）。
**编译期**另有一层保护：context 之间没有 `project(...)` 依赖，所以直接 import 根本编译不过。
`verifyArchitecture` 是防「有人偷偷加了依赖又顺手 import」的兜底。

**正确姿势**：

```kotlin
// teleport 里这样拿经济能力：
private lateinit var economy: SettlementAPI
economy = requireNotNull(Bukkit.getServicesManager().load(SettlementAPI::class.java)) { "Teleport requires economy" }
```

`api` 的接口签名里只出现 `UUID`、`BigDecimal`、`CompletionStage`——**没有 Bukkit 类型**，
所以「拿到 API 就能用」这件事本身就与平台解耦。

---

## 3. 依赖方向 `interfaces → application → domain`

**规则**：领域规则只写在 domain；application 只做异步编排与事件发布；interfaces 只做参数解析和权限；
infrastructure 实现领域端口。**不允许反向依赖**（domain 不得知道 application 的存在）。

**为什么**：否则业务规则会被 Bukkit API 污染，或散落到命令解析里，出现「命令和 API 行为不一致」。

**谁强制**：目录结构约定 + `Money`/`Wallet` 的自校验构造。
`Wallet.change`（`contexts/meowo-economy/domain/.../Wallet.kt`）对 `PAY_SENT`、`TP_RESERVE` 等
结算类操作直接 `throw IllegalArgumentException("Settlement operations require an atomic ledger transaction")`——
**结算类操作在领域层被明确拒绝**，必须走 `SettlementRepository` 的原子事务。这是领域层主动执行的规则，不是检查器。

**分层时的克制**：menu / render 没有建 `Repository` / `UseCase` 空壳。
`RenderService` 直接依赖端口 `FakeEntityRenderer`（一个 2 方法接口），`MenuContext` 直接编排。
**按复杂度决定层级，不要为了对称而填空**——见 `README.md:73`。

## 4. 公开 API 签名只用 JDK 类型

**规则**：`api/` 中所有对外类型的签名里不得出现 Kotlin `Result`、`Money`、`Bukkit Player`
或任何 context 的实现类。

**为什么**：两个目的——(a) Java 插件能直接消费；(b) 防止领域类型泄漏到跨 context 边界，
否则 `api` 就得依赖 domain 模块，红线 1 的"纯净"也会被绕过。

**当前形态**（`api/src/main/kotlin/com/meowo/api/`）：

| 类型 | 暴露的东西 |
|---|---|
| `EconomyAPI` | `balance/deposit/withdraw/setBalance(UUID, BigDecimal): CompletionStage<BigDecimal>` |
| `SettlementAPI` | 转账、传送费、预扣/结算/取消、每日补助、税收池 |
| `EconomyError` / `EconomyException` | 错误码枚举 + 异常 |
| `TransferReceipt` / `TeleportCharge` / `ChargeState` / `Settlement<T>` | 全部是 `data class`，字段只有 UUID/BigDecimal/枚举 |

**领域类型如何出入**：`Money` 只在 `Settlement<T>.changes` 之外出现，跨边界时统一转 `BigDecimal`
（`Money.decimal()`），读取时 `Money.of(...)`。`Settlement<T>` 这个包装是刻意的——它同时携带
**返回值**和**这次事务实际改动的账目列表**，后者是提交后发 `BalanceChanged` 的唯一依据。

## 5. 事件是通知，不是事务

**规则**：`BalanceChanged` 在**事务提交之后**才发布。订阅者抛异常只记录，不影响其他订阅者，
更不能把已提交的支付报告成失败。

**为什么**：事件总线不是持久化消息队列。提交后、通知前进程崩溃，通知会丢。
把通知做成「和提交同一个原子操作」会需要 outbox 表，收益不抵复杂度。
需要可靠通知的场景（比如菜单刷新）**重新查询**即可，菜单本来就是这么做的。

**谁强制**：`EconomyApplicationService.change`（提交 → `events.publish`）、
`EventBus.publish`（try/catch 每个订阅者，`build.gradle.kts` 无需改）；
测试 `EventBusTest`「ordered dispatch isolates failure」。

**对应地，关闭 EventBus 之后 publish 是 no-op 而不是抛异常**——这样关闭竞态不会把已提交的
支付误报为失败。见 `shared/.../EventBus.kt:26-27,41`。

## 6. 领域必须是真正独立的 Gradle 模块

**规则**：`contexts/meowo-economy/domain/` 在 `settings.gradle.kts` 里是独立 include 项
（`contexts:meowo-economy:domain`），不是 economy 的子文件夹。

**为什么**：文件夹隔离是约定，模块隔离是编译期强制。README 明确写了这一点
（`README.md:73`）——「真正的独立 Gradle 模块，而非仅按文件夹声称隔离」。

**后果**：`domain/build.gradle.kts` 只有一行 `api(project(":api"))`，连 `compileOnly(paper)` 都没有。
想在 domain 里 `import org.bukkit` 会直接编译失败。

---

## 7. 唯一入口，context 不是独立插件

**规则**：只有一个 TabooLib 入口 `MeowoCore`（`core/src/main/kotlin/com/meowo/core/MeowoCore.kt`）。
不用 `@TabooLib(id=...)` 多入口，不支持 PlugMan 单独卸载子模块。

**为什么**：单 jar 部署简单；生命周期由 `ContextManager` 显式管理，可预测。
TabooLib 子插件机制会让「停用顺序」变成隐式依赖，本项目需要显式可读的顺序（见 [02](02-运行时与生命周期.md)）。

**关闭/启用用配置开关 + `/meowo reload`**，不是 PlugMan。

---

## 8. 不使用 NMS，因此不需要 paperweight

**规则**：渲染层通过 PacketEvents 发包，不碰混淆后的 NMS 构造器。

**为什么**：NMS 每个 Minecraft 版本都变，跨版本基本要重写。PacketEvents 2.14.0 已经在
`compileOnly` 里提供稳定封装（`PacketEntityRenderer` 25 行就够）。

**代价（已接受）**：PacketEvents 是**独立可选服务器插件**（`plugin.yml` 的 `softdepend`）。
缺失时**只有 render context 启动失败**，economy / menu 照常工作——
`RenderContext.start()` 的 `check(isPluginEnabled("packetevents"))` 抛异常，
`ContextManager` 捕获、回滚该 context、记录堆栈，其他 context 继续。

**已知限制**：假实体 ID 用进程内递减负数（`RenderService` 的 `companion object AtomicInteger(-1)`），
与其他假实体插件并用会冲突，需要统一 ID 分配策略。

---

## 9. 版本号已核对，不要按 plan.md 的猜测编码

**规则**：以 `docs/versions.md` 的锁定表为准。`plan.md` 是**设计参考，不是可编译的 API 示例**。

**为什么**：`plan.md` 写作时假设 `26.2` 是「未知 fork」，并猜测需要映射到 `1.21.x`。
核对后结论相反：26.2 是正式版本，Paper API 坐标就是
`io.papermc.paper:paper-api:26.2.build.129-stable`，**不需要映射**。

**曾被 plan 误导而不采用的写法**（`docs/versions.md` 末段）：`@TabooLib(id=...)` 多入口、
`paper-mojangapi`、`PaperweightMain`。`plan.md` 里的示例代码**不要照抄**，
以实际源码为准。
