# 15 · chat 模块与风纪委员 AI 铺垫

## 1. 职责

`contexts/meowo-chat` 负责：聊天文案解析（过滤 / 格式化 / 表情）、**审核闸门**、审计缓冲，以及把插件自己的发言者变成**可被寻址的聊天参与者**。

不负责：处罚（未来的 `punish` context）、玩家间邮箱存储、AI 推理本身。

设计借鉴 [myth-MC/social](https://github.com/myth-MC/social) 的 parsers 模型，但把整条管线收进纯领域层，并给它加了一个 social 没有的前置环节——审核闸门。

## 2. 为什么领域层必须是独立的源码根

`domain/` 通过 `build.gradle.kts` 的 `sourceSets` 挂进模块：

```kotlin

sourceSets {

    main { kotlin.srcDir("domain/src/main/kotlin") }

    test { kotlin.srcDir("domain/src/test/kotlin") }

}

```

Gradle **不会**自动识别 `domain/`，必须显式声明，否则整个包对编译器不可见。

同时 `contexts/meowo-chat/domain` 被加进根 `build.gradle.kts` 的 `pure` 列表，因此领域层一旦 import Bukkit 就在构建期失败（[01 §1](01-架构红线.md)）。领域层连 Adventure 也不能碰：`Component` 是 Bukkit 生态类型，领域产出 `String`，由 bridge 负责互转。

**这条曾经只有文档没有门禁**：`verifyArchitecture` 当时只查 bukkit / papermc / taboolib。
它决定的是**谁有资格产出已渲染的组件**——而 domain 之所以输出 BBCode 而不是 `Component`，
正是靠这一条。2026-10-08 把 `net.kyori` 加进 `build.gradle.kts:57` 的 `forbidden` 列表并实测过它会拦
（[08 §44](08-坑与反模式.md)）。

## 3. ⚠️ MockBukkit 完全没有聊天事件

**这是本模块最重要的已知缺口。**

`mockbukkit-v26.2:4.116.1` 的 jar 里**一个 chat 类都没有**，`AsyncChatEvent` 同样没有。因此：

- `PaperChatBridge`（`ChatContext.onChat`）**无法**被集成测试覆盖；

- 任何依赖它的测试会被 JUnit 报成 **skipped 而不是 failed**——也就是 [08 §19](08-坑与反模式.md) 描述的静默陷阱：构建全绿，其实什么都没验证。

所以逻辑**全部**放在 `domain/`，用纯 JUnit 测；`ChatContext` 刻意保持为薄适配层。这是本模块测试策略的**前提**，不是偷懒。

## 4. 管线顺序（判定即契约）

```

归一化 → 审核闸门 → 脱敏 → 表情 → 格式化

```

两个顺序都不是随意选的：

- **闸门必须早于脱敏。** 风纪 AI 只看到 `***` 就没有证据可判、也没有东西可以拿去做申诉。`ModerationGateTest` 用「AI 拿到的必须是原文」这条断言锁住。

- **表情必须早于格式化。** `:not_an_emoji:` 里含下划线，若格式化先跑就会变成 `:not[i]an[/i]emoji:`，名字被吃掉。`ChatPipelineTest` 有专门的回归用例。

- 下划线强调要求**词边界**（`not_an_emoji` 中的 `_` 不算标记），与 Markdown / Discord 一致。

## 4a. ⚠️ 管线的输出词汇，和渲染层认的词汇，必须是同一套

`MarkupFormatter` 输出 **BBCode**：` **粗体** ` → `[b]粗体[/b]`。
这一节记录它曾经怎么送不到玩家眼前，以及为什么修法不是「让 markup 输出 `§`」。

**当时的错**：`[b]` 被交给 `LegacyComponentSerializer`，而它只认 `§`。
两套词汇谁也不读谁，玩家打 `**粗体**` 看到的是字面 `[b]粗体[/b]`。

**为什么不能改成输出 `§`**：那看起来是最小改动，但 `§` 是 U+00A7、
不是控制字符，能穿过 `normalise`。于是「玩家正要发出去的字符串」和
「一段序列化指令」再也分不开——玩家打 `§c§lADMIN` 就能拿到
红色加粗、看起来像服务器自己说的话。**格式码属于写这个字符串的人。**

**现在的切法**，按所有权分：

| 函数 | 用途 | `§` 是什么 |
|---|---|---|
| `ChatLine.plain` | 语言包 | 预期的格式（运维写的） |
| `ChatLine.body` | 玩家 / 模型产出 | **一个字符** |

`body` 是**渲染层唯一的正文解释器**，只认 `[b]` `[i]` `[u]`，
而且**只认成对的**：`[b]` 后面没有 `[/b]` 就是字面文本。
这让猫可以回答关于这套 markup 本身的问题而不把自己那句变粗，
也让玩家打出的方括号不会被吃掉一个字符。

它同时关掉了 `§` 注入的最后一个入口。私聊正文以前是
**无条件**反序列化的（`renderPrivate`），而公开聊天只在 emoji
改动了字符串时才反序列化（`ChatContext.onChat`）——
所以 `/meo msg Bob §c` 什么 emoji 都不需要就能上色。
现在 `§` 在渲染层根本不被解释，三条通道一起成立。

实测否掉的一条「发现」：`ChatContext` 那个 reader 配了
`.hexCharacter('#')` + `useUnusualXRepeatedCharacterHexFormat()`，
看起来 `&#ff0000` 就能直接上色、等于第二条注入路径。
实测 `&#ff0000ADMIN → coloured=false`，`§#ff0000ADMIN → coloured=true`。
**缺的就是那个 `§`**，所以 hex 配置没有独立的安全后果。

覆盖：`ChatLineBodyTest`（12）、`PrivateChannelFilterTest` 的两条正文断言。

## 4b. 公开聊天的渲染器：装上它，括号就没了

`ChatContext.onChat` 做两件事：把消息交给管线（改写 `event.message`），然后**装一个自己的

`ChatRenderer`**。第二件才是括号消失的原因。

Paper 的默认渲染器是 `Component.translatable("chat.type.text", displayName, message)`，

而 `chat.type.text` 在客户端语言文件里就是 `"<%s> %s"`。所以只改写消息正文是**改不掉括号**的 ——

事件里压根没有 `<>` 可删。

决定性的分支在 `ChatProcessor.complete()`（反编译实测）：

```java

key = (renderer instanceof ChatRenderer.Default) ? ChatType.CHAT : PAPER_RAW;

```

`paper:raw` 是**没有装饰**的聊天类型。插件装的渲染器都不是 `ChatRenderer.Default`，

一装就切过去，客户端原样显示渲染结果。

| 渲染器 | 客户端看到的 |

|---|---|

| Paper 默认 | `<Steve> 你好` |

| 我们返回 `Steve 你好` | `Steve 你好` ✅ |

| 我们返回 `你好`（只给正文） | `<Steve> 你好` ⚠️ 客户端照样套名字 |

用 `viewerUnaware` 即可：这一行对所有人相同，资料卡也是缓存值，

和 `ChatService.renderPrivate` 现在的做法一致。

> ⚠️ 这条**测不出来**。MockBukkit 没有聊天事件，而「装了渲染器就切 `paper:raw`」

> 是**服务器**的事实，不是本仓库代码的事实。`ChatLine.publicLine` 能钉住形状，

> 括号是否真的不见了仍然要真机确认。

## 5. 私聊必须过**整条**管线

两条私聊通道都走 `ChatPipeline.process()`：`/meo msg <猫>`（`directMessage`）
和 `/meo msg <玩家>`（`postToPlayer`）。

这一节以前写的是「走的是 `ModerationGate.decide()`」，
并且把闸门当成了过滤器。**那是错的，而且错得很有说服力。**

`ModerationGate` 只**判定**，不打码：它对过滤词返回
`ModerationAction.REDACT` + `replacement = null`，同时把**原文**一起返回。
真正把词换成 `***` 的是 `RuleSet.redact()`，而它只有 `ChatPipeline` 会调。

于是配置里的每一条字面量和正则过滤词都曾经是「只对公开聊天生效」的规则：
玩家想让某个词出现在屏幕上，把它打进私聊就行了，两条通道都照办。
旧代码上面那句「the same gate, the same rules … the single most important line
in the file」把它钉在了那儿 —— 一行读起来像承重墙的代码，正好是没人复查的那一行。

变异运行（把两处改回只调闸门）实测：

```
a filtered word is masked before another player ever sees it
  → §8#lmem§r §7✉§r meov0 §8→§r Bystander §a✔§r 我们去 违禁词 吧
a filtered word is masked before a cat is asked about it
  → [我们去 违禁词 吧]
```

**代价是明码标价的**：私聊从此也会吃到 emoji 和 markup，和公开聊天一致。
这条交换是主动做的 —— 两条不会漂移的通道，比两条今天恰好一致的通道值钱；
而「记得在每个新调用点补一次 `redact`」正是刚刚失败的那个办法。

参考锚点仍然正常：回复行**本来就会**在正文前显示它答复的编号
（`ChatJournal.refCode` 就是 `record.anchor`），所以断言数的是**出现次数**而不是有无 ——
一次是徽章，第二次才是锚点漏进了正文。

## 5a. 猫主动开口：玩家用了自己的指令，且额度还在

`/meo <route>` 跑完之后，**拥有这条 route 的 context 对应的那只猫**可以主动说一句话。

```
玩家执行 /meo eco balance
        ↓  CommandRouter.onCommand（只有真正跑成功才通知）
        ↓  routeOwners[route] → "economy" → CatRegistry.byId → EconCat
        ↓  settings.proactive && budget.hasRoom(PROACTIVE) && backlog == 0 && roll < 5%
        ↓  CatSink.offerProactive
        ↓  ✉ EconCat → meov0 ✔（私聊，不进公开频道）
```

### 为什么触发条件是「用了它的指令」，不是「玩家沉默了一会儿」

沉默计时器要么打扰人，要么需要一个额外状态来解释它。
而**玩家刚用过某个功能**，是唯一一个「他此刻确实想从这只猫这里得到点什么」的时刻，
而且不需要向运维解释任何新东西。

### owner 从哪来

`routeOwners` 由**和 `commands.list` 同一个 `observe` 回调**填充——
一条 route 不可能「一边被记录、一边查不到归属」。
手写一张 `route -> cat` 表就是第二个真相源，而 `CommandRouter` 存在的理由恰恰是
「route 名和 context id 不是一回事」（`eco` 不是 `economy`，`tpa` 不是 `teleport`）。

### 全部门槛（便宜的在前）

| 门槛 | 挡掉什么 |
|---|---|
| `settings.proactive` | 服务器没要就别给。**默认关** |
| 发令者是 `Player` | 控制台不是聊天对象，对它说话会写进日志 |
| `routeOwners[route]` 存在 | 没人声明归属的 route 不猜 |
| `cat.id in AGENT_CATS` | 另外七只猫没有工具，开口就是编 |
| `budget.hasRoom(PROACTIVE)` | **资源充足**：当天的主动份额还有余额 |
| `backlogDepth() == 0` | 不跟真人排队的问题抢 |
| `roll < 0.05` | 5% |
| `CatSink` 内部的冷却 | 同一只猫对同一个玩家 10 秒内不连着说 |

最后一条**故意放在 `CatSink` 里而不是调用方**：这是主动通道唯一的门，
「别太密」属于门。要是留给调用方，它就变成这个项目反复找到的那种形状——
每个新触发点都记得这个闸门，直到有一个不记得。

主动问候**不占用提问冷却**：共用一个时间戳的话，猫刚说完话就会拒答那句被它邀请的提问。

### 这套东西曾经是完整的、也是没人调的

`offerProactive`、`Lane.PROACTIVE`、`droppedProactive`、`proactiveShare` 全都写好了，
零调用者。**变异运行（`if (true) return` 关掉整个触发器）当时全仓库测试全绿**——
端到端测试是后来才补的（`ProactiveTriggerTest`），现在同一个变异会让它变红。

覆盖：`ProactiveTriggerTest`（8）、`ProactiveLaneTest`（8）、`CommandRouterRunTest`（6）。

## 5b. 两条通道，互不重叠

```

/meo msg <玩家或发言者> <内容>    私信

/meo mail                        邮箱

/meo em [名字]                   表情表 / 查一个名字（支持 Tab）

/meo who                         发言者名册

/meo chat                         诊断信息（OP）

```

公屏那一行的名字和私信、Cat 的名字**行为一致**：悬停出资料卡，点击预填 `/meo msg Bob `。

玩家和猫都能私聊 —— 只有这里不一样的话，看起来像疏忽而不是决定。

**送达回执是那一行本身**，不用 actionbar——actionbar 三秒就消失，通知很容易回。

`postToPlayer` 给双方都渲染同一行，`✔` 在线直推、`〇` 已进邮箱。

**成功不再另发一条提示**：原来还会跟一句「✔ 已把私信发给 Bob」，而那一行就在上面，

`✔` 已经说完了同一件事，两条消息在刷屏。失败仍然出声（`msg-refused-*`、`msg-unknown`），

因为失败时根本没有行可看。

## 5c. 点哪里，是什么

```

#k3f9 ✉ Alice → Bob ✔ 在吗

```

| 点哪里 | 得到什么 |

|---|---|

| **发件人的名字** | `/meo msg Alice ` —— 和这个人开一条**新的** |

| **收件人的名字** | 发件人那一份才有点击：`/meo msg Bob `（收件人看到的是自己，安静） |

| **消息本体** | `/meo msg Alice #k3f9 ` —— 回**这一条**，带码 |

| 行首 `#k3f9` | 只悬停（谁 / 何时 / 几条回复），**不点击** |

> **自己那一行不挂点击**，这是刻意的：名字是自己、正文也是自己，点下去就是

> `/meo msg <自己>` —— 一个必然被拒的地址。

> ⚠️ 但这意味着**单人测试服上永远看不到这些点击**：屏幕上每一行都是你自己的。

> 要验证请用**第二个玩家**，或者去看别人发的那一行。

**这条规则对每一种消息都一样**，不是私信的特例：

| 消息 | 点名字 | 点正文 |

|---|---|---|

| 玩家公屏 `#k3f9 Alice 你好` | `/meo msg Alice ` | `/meo msg Alice #k3f9 ` |

| 私信 `#k3f9 ✉ Alice → Bob ✔ 在吗` | `/meo msg Alice ` | `/meo msg Alice #k3f9 ` |

| 邮箱每一行 | 同上 | 同上 |

| Cat 应答 `#k3f9 ✉ EconCat → Bob ✔ 收到` | `/meo msg EconCat ` | `/meo msg EconCat ` |

| **Cat 通知 `#k3f9 ✉ EconCat 已转账`** | `/meo msg EconCat ` | `/meo msg EconCat ` |

最后一行曾经是**唯一的例外**：通知正文不可点，想问这只猫刚才说了什么，

只能瞄准五个字符的名字。一个插件在这一点上不统一，看起来就像拼出来的而不是设计出来的。

> 点击挂在**正文本身**而不是它的子节点上：长句仍然可以选中复制，

> 读者可以先选中一个词，再决定要不要理它。

**名字是人，消息是一个时刻。** 两者做的事不同，所以不能合成一个点击：

点名字开空白对话，点正文回这一句。行末那个 `↩ 回复` 按钮就是多余的 ——

它和正文说同一句话，只是在每行多花五个字符，还让「回复」看起来像一个额外控件，

而不是你对别人说的话做的事。已删。

**空命令 = 不挂点击。** 同一行发给双方，发件人看到的是**自己的名字**在发件人位置；

挂一条 `/meo msg <自己>` 就是让她私聊自己。公屏同理：说话的人看自己的那一行时，

名字和正文都安静下来（[08 §26](08-坑与反模式.md)）。

⚠️ 实现上必须走 `component(sender, key)`（内部 `LEGACY.deserialize`），

**不能**用 `Component.text(text(...))`——后者会把 `§7` 当普通字符塞进去，

玩家看到的是字面量 `§7✉`。`PrivateBadgeTest` 断言纯文本序列化结果不含 `§`���

正是为了锁住这一点。

## 5c-2. ⚠️ 同一行给两个人看，点击就必须按读者分

发件人也会看到自己发出去的那一行（回显），所以一行里有两个名字、还有一个「对方」：

```

#k3f9 ✉ Alice → Bob ✔ 在吗

```

收件人 Bob 点 `Alice` 开新对话，点正文回这一句；

发件人 Alice 看到的是自己的名字，`other` 换成了 Bob。

修法在 `ChatService.renderPrivate`——渲染时就分清读者：

```kotlin

val iAmSender = viewer.name.equals(from, ignoreCase = true)

val other = if (iAmSender) to else from

val msg    = if (iAmSender) "" else ChatLine.msgCommand(from)

val reply  = ChatLine.replyCommand(other, record.code)

```

> 凡是「一份数据、两方可见」的界面，点击行为就不能只算一份。

> KDoc 曾经写着「reply 快捷键按读者分别解析」，而代码里是两边共用同一条命令——

> **注释描述了意图不等于实现了意图**，这种不一致单测也不会报。

## 5c-3. 资料卡：猫和玩家同一套，按查看者的语言

悬停任何名字弹出的卡片，标题、画法、交互**完全一致**，不因为是真人账号就换个说法：

```

资料

名字 Alice

UUID 069a79f4-…        ← 只有这一行的值可点，复制的是这行显示的 UUID

注册 2024-03-11

在线时长 12m

累计游戏 389d 18h

余额 120.00 Meo

```

Cat 的卡片同形状，只是多两行——它没有账号，职责就是它的全部说明：

```

资料

名字 EconCat

职责 余额、转账与每日补助

回复方式 /meo msg EconCat

```

| 规则 | 原因 |

|---|---|

| **文案按查看者解析** | `ProfileCache` 原来用的是 `messages.text(key)` —— **不带 viewer**，永远走服务端默认语言。英文客户端看到的就是中文卡片 |

| **不写「点击可私聊」页脚** | 页脚里的 `/meo msg <名字>` 是写死的。看到自己卡片的人一点就是私聊自己 |

| **UUID 值本身可点** | 「复制 UUID」就得真的复制 UUID。原来挂在名字上的是**复制名字**，名副其实地复制了 id |

| **标题走 `messages.component(viewer, …)`** | `Component.text("§b资料")` 会把 `§b` 当字面量，卡片开头直接显示 `§b资料` |

| **时长不是 ISO-8601** | `Duration.toString()` 给的是 `PT9354H11M`。那是线路格式，不是给人读的时长 → `Durations` |

按查看者解析意味着**公开聊天也必须用 viewer-aware 渲染器**：

`ChatRenderer.viewerUnaware` 只渲染一次、发所有人，

英文玩家拿到的还是服务端默认语言那一版。

## 5d. 在线直推，离线入箱

```

/meo msg Alice 你好    Alice 在线 → 直接渲染进聊天栏，不进邮箱

/meo msg Alice 你好    Alice 离线 → 存进邮箱，/meo mail 查看
```

在线还存一份的话，收信人要读两遍。在线推送时还会把 Alice 留在你邮箱里的信标记成

## 5e. 邮箱

```

/meo mail

── 邮箱 · 5 封 · 未读 2 ──

✉ <Alice> 你在吗          ← 未读，亮蓝

✉ <Bob> 上次那个事        ← 已读，暗

✉✓ <Carol> 收到，回了   ← 已回，带勾

```

打开邮箱会把展示出来的全部标记为**已读**，所以「未读」永远只算真正没看过的那些。

回复某个人之后，他留下的信全部标记为**已回**。

**落盘**：独立 SQLite `plugins/Meowo/chat/mail.db`，重启不丢。

形状照 `meowo-mine` 的 `MineLedger`——**缓存而非查询路径**：启动时读进内存，之后

命令只碰内存，落盘只在真的有变化（新增 / 标已读 / 标已回 / 修剪）时发生，

命令处理绝不在 SQLite 上阻塞。放在独立文件里而不是 economy 库，是为了不让任何

context 依赖另一个 context 的实现（红线 §2）。

有界（默认 32 封/人，超出丢最旧的），并对同一对玩家做 3 秒限流。

```

/meo msg Steve 你好     ← 投递（回执进 actionbar，Steve 那侧弹提示条）

/meo msg                ← 读自己的邮箱，读完即清空

```

`Inbox` 是纯领域对象，有两个刻意的设计：

- **有界**（默认 32 条/人，超出丢最旧的）——无界邮箱就是「多了几步的内存泄漏」，一个恶意客户端能给每个在线玩家都灌满。

- **限流**（同一对 3 秒一条）——挡互刷。

退出时随 `forget` 一起清掉，重连不会继承旧消息。

**当前是内存实现，重启即丢。** 需要留证时再仿 `meowo-mine` 的 `MineLedger` 落盘。

## 6. 发言者一等公民化

`Messages.say(sender, speaker, message)` 本来就能以任意发言者说话，所以「让猫成为玩家」不需要改造消息系统，只要补两样东西：

1. **可寻址的身份** — `Participant.System(id, handle, summary, answerable)`

2. **收信出口** — `SystemSpeakerSink`

`SpeakerDirectory` 在 `start()` 时从 `Messages.speakerIds` 快照一次。名字**同时**匹配显示名（`EconCat`）和原始 id（`economy`），两者指向同一只猫。

## 7. 名称歧义：系统优先

玩家改名 `EconCat` 后，`/msg EconCat` **仍然**发给系统发言者。让玩家能冒领系统身份，意味着任何发给某只猫的消息都可能被截走——这比「叫猫名字的玩家发不出消息」严重得多。

`chat.player-first: true` 可以反转，但服主要自担冒名风险。

## 8. 风纪委员 AI 怎么接入

三个接缝，全在 `api/`：

| 接缝 | 用途 |

|---|---|

| `ChatModerationAPI.register` | 在聊天路径上判定（**必须 <1ms**，禁止阻塞 IO） |

| `ChatModerationAPI.setRisk` | **带外**算分后回填，闸门 O(1) 读表 |

| `ChatModerationAPI.claimSpeaker` | 应答 `/msg <猫> …`，即「上线」 |

**AI 不在请求路径上同步阻塞。** 闸门只做本地确定性判定；AI 慢 10 秒，聊天毫无感知。`RiskRegistry` 自身会随时间衰减，所以远端调用失败时风险分自然回落。

审计缓冲用 `AuditBuffer`，固定容量环形覆盖（默认 512），重启即丢。需要留证时再仿 `meowo-mine` 的 `MineLedger` 落盘。

## 8b. 猫的聊天范围，和它们所在的世界

十二只猫以前只共用一句「你是本服某某」的人设，各自只有一句口吻，于是有三种失败同时发生：
**说什么都一样**，**说话也一样**，**连名字都对不上**。现在每只猫多三个字段，提示词多三段。

### 八个字段，不是八个形容词

`CatProfile` 里管"人味"的有六样，一样管"知道什么"：

| 字段 | 干什么 | 写错的后果 |
|---|---|---|
| `persona` | 它**是谁**（身份 + 脾气） | 十二只猫写成同一段说明文 |
| `tone` | 它**怎么说**（语域） | 十二只猫用同一个语域 |
| `mbti` | 一个**性格代码** | 一段形容词，模型做不出来 |
| `personality` | 这个代码**落到它身上**是什么 | 只有一个标签，没有行为 |
| `quirk` | 一个**具体习惯** | 形容词不是习惯，模型做不出来 |
| `deflect` | 它**怎么承认不知道** | 一问不知道就变成客服腔 |
| `sample` | 一段**两行示范** | 只描述声音等于没示范 |
| `scope` | 它**管哪一块** | 什么都能答 = 什么都不像角色 |

### 名字：英文的，而且是唯一的

玩家在聊天框里只见过 `<EconCat>`，能打的也只有 `/msg EconCat`。而人设原来写的是
「你是本服的精算师」—— 于是模型学会了**第二个名字**：它自称精算师，它把玩家支去「问房东」，
玩家一个都照着做不了。

所以每只猫的人设**以英文名开头**，提示词里另有一条规则：猫只有名字，没有职位。

> - 猫只有名字，没有职位。提到自己或者别的猫时用名字（MeowCat、EconCat、TeleCat…），
>   别说「快递员」「精算师」「房东」「地质学家」「风纪委员」——玩家要打的是名字。

规则里**列全部名字**，是因为不列模型就会自己编：它不知道 `NestCat` 叫什么，
于是按中文职位翻译出一个「房东」。名字是玩家唯一握得住的把手。

### `mbti`：一个 token 换来的方向感

MBTI 在这里**不是性格测评**，是给模型用的**行为速记**。它重要不是因为准，是因为**可查**：

- 十六个码，十二只猫，**两两不同** —— 这条能写进测试；
- 一段形容词写不出这个保证，因为「严谨」「稳重」没有互斥性。

代码单独用是标签，所以每个码后面跟一句**落到这只猫身上的行为**：

```
类型：ESTP
落到你身上是：盯当下、行动派、嘴上爱催人。答应一趟活就一定送到；路上出了岔子他第一个骂，骂完还是先把人送到。
```

提示词里另有一句：**别把「ESTP」这种词说给玩家听** —— 没有这句，模型会开始自我介绍
「作为一只 ESTP，我建议你……」。玩家没要人格测评。

### `scope`：范围是**聊天**范围，不是工具范围

`scope` 说清两件事：**哪些是我的地盘**，**哪些不归我管**。后半句不能省 ——
只写「不归我管」会被读成「没说不能」；只写「是我的地盘」则会让每只猫都答所有问题。

七只**没有工具**的猫最容易撞上这个矛盾：`scope` 说「坐下、起身归你管」，
提示词另一头说「你**没有任何工具**，因此你不知道服务器上的任何数据」。
两句挨着读就是矛盾，所以提示词在范围段后面补了一句：

> 这一块是你**能聊的范围**，不是你能查的范围：具体到某人某事，你手里没数据，让对方去问 MeowCat。

**范围与工具是两件事**：有工具的猫在自己的范围内既能聊也能查；没工具的猫在自己的范围内只能聊。
这条区分由 `CatScopeTest` 双向断言 —— 没工具的必须有那句，有工具的**不许**有那句。

### 世界边界只写一次

十二只猫共用一段世界边界（`PromptBuilder.WORLD_BOUNDARY`）：

> 你的世界只有这台服务器和 Minecraft：地形、怪物、装备、箱子、矿脉、命令，还有进来的人。
> 现实世界那边对你来说是空白的——不是保密，是压根不在你脑子里。
> 对方把话扯到那边，你就是不知道：直说「这个我帮不上」，或者把话头带回服里。

两处刻意的写法：

- **写成事实，不写成禁令。**「现实世界的事别答」留了一个口子：模型会拿玩家刚提到的东西去猜。
  「那边对你来说是空白的」没得猜 —— 只能答「这个我帮不上」。
- **只写一次，不逐猫写。** 十二只猫就是十二次把边界说松的机会，而最松的那句会赢。
  `CatScopeTest` 直接断言十二只猫的「## 你的世界」这一段**逐字相同**。

逐猫的范围（`scope`）不许越过这条边界：`CatScopeTest` 里有一张现实世界词表盯着，
`scope` 也不许带数字、坐标、UUID、货币单位（和 `sample` 同一条规则，规则写在 `ProfileText` 里，只有一份）。

### 话说多长：由性格决定，不由全局决定

原来提示词里写着「一次只回一两句」，**每只猫都一样** —— 一屋子沉默的猫。
现在这条改成了「一次把话说完，你说多少是你自己的性格」，字数上限从 **220 提到 320**。

上限提高是有代价的：**思考和正文共用同一份额度**（`max_tokens`）。
推理模型的思考要占掉一截，320 字的回复自己又要好几百 token，512 只够思考。
所以 `agents.max-tokens` 的出厂默认从 512 提到 **1024**。

> ⚠️ **老服务端要自己改**：`ConfigVersionMerger` 的规矩是「只补缺失的键，不动已有值」，
> 所以已经写着 `max-tokens: 512` 的 `config.yml` **不会**被自动改掉，得手动改成 1024。
> 不改的后果不是报错，是**聊得多的猫被从中间截断** —— 半句话消失，比说得短更像坏了。

`AgentInfrastructureTest` 断言 `DEFAULT_MAX_TOKENS >= MAX_REPLY_CHARS * 2`：
以后谁把回复上限调高却忘了调预算，测试会红。

### 这套东西被谁盯着

`CatScopeTest` 12 项 + `CatPersonalityTest` 11 项：

- 每只猫都有 `scope`，且两只猫的范围不重样；
- 范围出现在提示词的「## 你管什么」段里，不是散落在别处；
- 十二只猫的 `persona`、`tone` 各不相同，`sample` 都是两行的真示范；
- 人设以**英文名**开头；提示词里列全部名字、并点名禁止中文职位称呼；
- 十二只猫的 `mbti` **两两不同**且都在十六个码里；`personality` 也两两不同；
- 每个码都带着「别把「ESTP」这种词说给玩家听」这句护栏；
- 回复上限 ≥ 300，提示词里不再有「一次只回一两句」；
- **至多三分之一**的猫是「话少型」—— 都短就等于没分化。

> `tone` 那条一开始是红的：`shadowbox` 和 `spawn` 的语气都写着「简短。」——
> 两只猫共用一个语域，正是这一节要治的病。测试比人眼先发现。

## 9. 异常隔离与 fail-open

审核器抛异常时：捕获 → 记日志 → **跳过该审核器**，其余继续。消息本身是否放行由 `chat.fail-open` 决定，默认 **open**——审核助手挂了不该让全服聊天瘫痪。

单个审核器不影响其他审核器，`ModerationGateTest` 锁住这条。

## 9b. 每条消息一个 `#k3f9`

```

#k3f9 Alice 你好

#k3f9 ✉ Alice → Bob ✔ 在吗  ↩ 回复

#k3f9 ✉ EconCat 你好，余额 ฿120.00

```

**每条**消息都带 —— 包括猫自己的通知。「服务器刚才 21:24 跟我说什么来着」是真问题，

而 `/balance` 的输出正是会被问到的内容。猫的消息不指向任何东西、也不会收到回复，

所以只占一行记录，永远不会出现在别人的会话串里。

| | |

|---|---|

| **形式** | 随机 4 位 base36（`#k3f9`），36⁴ = 167 万种 |

| **不用递增号** | `#233 #234` 等于免费送出一个「今天服务器多忙」的计数器 |

| **不用 3 位数字** | 900 个值，撞几次就穿帮，而撞号会让「点击查看关联」指到别人的记录 |

| **悬停** | 谁 + 什么时候（`Alice → Bob · 2026-10-06 21:24:33`） |

| **点击** | 跑 `/meo replay #k3f9`，打印**嵌套回复树**（不是把消息再打一遍） |

| **回复携带** | 预填成 `/meo msg Alice #k3f9 `，正文**自动显示被回复的那条** |

### 回复：把「被回复的编号」放在正文前面

```

#k3f9 ✉ Alice → Bob ✔ 在吗

#bbbb ✉ Bob → Alice ✔ #k3f9 收到

                     ^^^^^^ 悬停 = 它在回哪一条 · 点击 = 拉出会话树

```

这个位置试过三种形状，全都不对：

| 形状 | 结果 |

|---|---|

| 什么都不显示 | 回复和一条新私信**一模一样**，看不出引用过任何东西 |

| 正文前印 `❝被回复的那句话` | 「很丑」—— 一句话说的事变成一段话 |

| 短码前加 `↩` | 还是**两套记号**：开头有自己的码，前面又有一个符号 |

| **正文前放被回复的码** | ✅ 用的就是插件本来在说���种语言 |

悬停那个 `#k3f9` 显示的是**整条链**，从根到它直接回的那一条，一行一跳：

```

#aaaa  Alice → Bob  在吗

#k3f9  Bob → Alice  收到

```

所以「回复的回复」不用一层层点进去才看得见 —— **嵌套就是这条链**。

点击跑 `/meo replay`，爬的是同一条链。

⚠️ 有没有引用**只看字符串是否为空**，绝不能问组件「有没有子节点」：

叶子组件没有子节点，那个判断会把分隔空格吃掉。同一个坑踩了两次。

### `/meo replay` 的每一行都不该有 `✉ MeowCat`

回放是**转储**，不是谁在说话。每一行都走 `messages.send` 时，每行都被盖上自己的
`#k3f9 ✉ MeowCat` —— 六句话的对话重复六次 `MeowCat`，还给没人写过的行发了六个新码。

新增 `Messages.sendPlain`：不套发言者、**不打码**。`/meo replay` 的每一行本来就带着
它所展示那条消息的编号，再盖一个就是噪音。

输出形状（**两行一段、不缩进**）：

```
#k3f9 │ 2026-10-06 21:24:33
在吗
#8i5f │ 21:24:40
收到
```

只留编号和时间、正文单独一行。之前那一行塞了「编号 │ 发送者→收件人 │ 时间 │ 正文」，
而在一段对话里**发送者和收件人每行都一样**，那列信息量还不如它占的宽度；
缩进本来是想表达嵌套，结果又变成要跳过去读的另一种形状。顺序仍是根在前，回复跟着它回的那条。

⚠️ 对照：`/meowo help` 那种**一条消息内含换行**的多行块，发言者只出现在第一行 ——
`MeowoRuntimeTest` 里 `a multi-line block names its speaker exactly once` 钉住了这一点
（恰好一次，且整页是一条消息而不是每行一条）。

### 只发编号的「回复」会被拒

点正文预填的是 `/meo msg Alice #k3f9 ` —— 光有编号**没有内容**。直接发出去会投递一行

没有字的消息，在发件人自己那份上看起来就像「我的回复消失了」。所以直接拒收并说明。

### 运维语言文件不能改坏格式

语言文件允许管理员覆盖文案 —— 这是它的用途。但**覆盖一个改了形状的格式不是**：

`replay-row` 从 3 个占位符长到 4 个之后，一份旧文件继续用旧的 3 个，

结果就是会话树**静默少一列发送者、缩进也读不出来**，而且没有任何报错。

`Messages.readBundle` 现在比较占位符集合：**形状对不上就以 jar 里的为准**。

被覆盖的是句子，不是布局。键名也一并从 `replay-line` 改成 `replay-row` ——

旧文件里有前者、没有后者，自然落到新格式上。

### `#` 不再可点，`/meo replay` 改成一棵干净的树

**行首的 `#k3f9` 只悬停，不点击。** 一个「点开就能读这条消息」的点击是错的承诺 ——

消息本来就在屏幕上，`replay` 回答的是「**别人还说了什么**」。每行两个大部分时候什么都不做的字符，

比完全没有这个提示更糟。命令照样能手打，要进对话树的路在 `↩ 回复` 上。

树本身：

```

#k3f9 │ Alice → Bob │ 2026-10-06 21:24:33 │ 在吗

  ↳ │ Bob → Alice │ 21:24:40 │ 收到

    ↳ │ Bob → Alice │ 21:24:52 │ 在的

```

三条让它像**对话**而不像日志的规则：

| | 原因 |

|---|---|

| **只有根带码，回复带 `↳`** | 每行重复 `#bbbb` 就是日志转储；缩进已经说明了谁回谁 |

| **缩进在行首** | 夹在码和名字中间就成了噪点，眯着眼看的树不算树 |

| **每行四个字段全给**：码/作者/时间/正文 | 只给码等于什么都没给；正文不截断 |

**点任意一条都能看到整段对话**（`ThreadLog.conversation` 先往上爬到根）。

点一条**回复**的码只看它的子树是答错了问题 —— 而父消息恰恰是读者在屏幕上**看不到**的那一半。

爬升由 visited 集合兜底，玩家手改预填命令造出的环会停在某个根，而不是卡死。

`ThreadTree.nest` 是纯函数，父缺失提升为根 / 环切断 / 深度有界都能测。

**历史经常是不完整的** —— 环形缓冲和 7 天留存都是部分的，父消息早被挤掉的回复很常见。

那种回复**提升为根**而不是被丢掉：丢掉就正好丢掉了读者特意找来的那一行。

玩家手改预填命令能造出环，靠 visited 集合切断而不是卡死。

### 谁分配状态码

**发送方，一次。** 私信是同一行发给双方的，码如果在 `deliver` 里铸，两边就会拿到**不同的码**，

点收件人那个码打开的会话串里根本没有他刚看的那句话。所以每个「产生一条消息」的渲染点铸一次码，

往下传：`postToPlayer` 铸一次，两份副本共用。

### 码必须全局唯一，而不只是「内存里不重复」

码空间是 36⁴ = **1 679 616** 个。内存环形只有几千行，磁盘上却留着**几周**的记录——
所以只跟内存去重，铸出来的码可以撞上**早就写进盘里**的那一行。

撞上之后的旧行会被 `INSERT OR REPLACE` **删掉**再写新的：旧消息永久消失，读者的 `#k3f9` 指向了
别人的那段对话。所以现在：

- **`CodeBook`** 用一个位图（210 kB，一个 bit 一个码）记下所有用过的码；**开局时把盘上已有的码读进来**，
  之后每铸一个就占一个——**码只用一次**。
- 写盘用**普通 `INSERT`**：真撞上了就**失败**并进日志，**没有任何东西被销毁**。唯一性由构造保证，
  拒绝只是最后一道背书。

### 记录存在哪

内存环形（默认 4096 条）+ SQLite（`chat/log.db`，**保留 15 天，按玩家最后一次登录算**）。

- **内存**是权威，读 `/meo replay` 优先走它；被挤掉的老码才回落查盘。

- **写盘永远不阻塞聊天线程** —— 单线程 worker + **有界队列**，溢出的行被丢弃并计数，

  而不是把某个玩家的聊天卡住。

### 保留期按「最后一次登录」算，不按消息日期

原来的规则是 `sent_at < 7 天前` —— 按**行龄**删。这条规则会对一个天天上线的玩家撒谎：
他三月说的话照样在四月被删掉，因为那行够老了；而他昨天刚说的话，因为他一个月没来，
早就没了。**日历时间和「这个人还在不在」是两件事。**

现在的规则：`chat_active` 表记着每个玩家**最后登录的时间**，删的是
**超过 `chat.log-days`（默认 15）没登录的人的聊天**。三个分支各有具体理由：

1. **作者不再上线** —— 他自己说过的话。
2. **收件人不再上线** —— 「对应聊天」是对称的。**Bob 手上的 Alice 那份副本也是 Bob 的数据**，
   而且通常**只有收的那个人不知道它被存了**。
3. **不属于任何人、且够老的行** —— 服务器公告、`/balance` 回显没有主人，
   否则它们就是磁盘上唯一永不消失的东西。

> 钩子是 `PlayerJoinEvent`，**不是消息**。天天登录但一句话不说的人，
> 我们照样留着他说过的话 —— 用消息做信号会「因为他安静」而删掉一个老玩家的全部历史。
> （`ChatContext` 里 `PlayerJoinEvent` 曾经 import 了却从没被用过，正好是缺的那个钩子。）
> `/reload` 不会为已在服上的人触发 join，所以 `start()` 里再补一次播种。

**升级不会抹掉老库**：`chat_active` 是新表，老库里的人一个都没有。
若把「没有登录记录」当成「从没登录」，第一次清理就会抹掉全部历史 ——
所以开库时用 `INSERT OR IGNORE` 从每行自己的 `MAX(sent_at)` 回填一次登录时间。
玩家的最后一条消息是他最后一次登录的**下界**，绝不会更高；
最坏情况只是升级后**第一次**开机时把某人忘得略早一点，他下次登录就修好了。

**代价（说清楚）**：活跃玩家的行**不再按日期删除**，表增长的是「当前在场的人说了多少」，
而不是日历时间。这是这条承诺换来的东西 —— 但它是交换，不是白拿。
所以 `chat.log-days` 现在的含义是**「缺席多少天」**，不是「保存多少天」。

`ChatLogStore` 此前**一行测试都没有**。上面每一条现在都有对应断言，包括
「300 天前那一行，因为人昨天还登录过，所以留着」—— 这条是最先会被悄悄改回去的地方。

### 会话串是读时算的

写的时候不维护任何树。`#k3f9` 那条 + 所有 `anchor` 指着它的行，广度优先、最多 8 层、默认 24 条。

父消息被挤掉的回复**照样能查**，只是自己成了串头 —— 这是诚实的结果，

比让引用悄悄消失好。玩家手改预填命令能造出环（A 回 B、B 回 A），靠 visited 集合切断。

### 任何人都能看

`/meo replay #k3f9` 不设权限。另一种做法是让「他 21:24 给我发了什么」这种问题只有管理员能答，

而读者自己点不开的码，压根不算码。

## 10b. 正则 ReDoS 防护

管理员写的正则会跑在**每一条消息**上，灾难性回溯会卡住聊天线程。`RegexRule` 在构造期就拒绝嵌套量词（`(a+)+`、`(a*)*` 等），并对输入长度设上限。

## 11b. 两个接缝曾经只接了一半

两处都是「接口公开了、代码也写了、但**没人插上去**」，单测和实机都看不出来。

**禁言。** `ModerationGate` 一直有 `withMuteCheck`，`ChatModerationAPI.muteUntil` 也一直公开，
但 `ChatService` 从没调用过 `withMuteCheck` —— 闸门里的检查问的是 `{ false }`。
全仓库只有 `meowo-agents` 调 `isMuted`，所以**通过 API 禁言的玩家，公屏照样能说话、私信照样能发**。
现在接在闸门上：一处覆盖所有路径（公屏 / 玩家私信 / 猫），而不是让每个调用点自己记得问。

**风纪审核器。** `ChatModerationAPI.register(moderator)` 把审核器加进 `ChatService.moderators`，
用于 `onPublished` / `onQuit` 通知；**判定**却遍历闸门自己那份 `auditors`，而那份从来没人填。
于是每个注册进来的风纪 AI 都被告知发生了什么，**却从不被问「这条该不该放行」**。
接口存在的理由接上了一半。现在 `register` 同时登记到闸门，关闭句柄两边都摘。

**为什么没被发现**：`meowo-agents` 明确不注册审核器（它在热路径上），所以两个 context
互相看不见对方的洞；纯领域测试测不到「谁被调用」，只测得到「判定逻辑对不对」。

> 这类 bug 的形状是：**能力看起来存在，实际上没有接线**。
> 判据很简单 —— 每个公开的注册/配置入口，都要有一处测试证明它**真的被调用**，
> 而不是只证明它能被调用。

## 11c. 被拦下的消息必须出声

`Outcome.Drop` 之前只做两件事：取消事件、发 `ChatMessageBlocked`。玩家看到的是
自己的话凭空消失，没有半个字。

这套闸门当初刻意把 **AI 判定排在脱敏之前**，就是为了让审核器看到原文、让申诉有据可查 ——
结果证据收下了，两端都没有人拿到。而**没有解释的拦截是无法申诉的**，闸门也就白设了。

现在拦下时给玩家一句「这条没发出去」/「你被禁言了」，**但不透露原因** ——
说「命中了过滤词表里的某个词」等于在教人绕过。细节留给审计和管理端，那才是申诉能被回答的地方。

> 顺带一个实测结论：**字面过滤器只脱敏，不拦截**。`chat.literal-filters` 命中的是
> `Outcome.Send`（词被替换成 `***`，消息照发）。真正会 `Drop` 的是注册的审核器和
> `chat.max-length`。测试里想造一次拦截，必须走 `ChatModerationAPI.register`，
> 塞字面词是测不到拦截的 —— 我第一次就是这么写错的。

## 13. 猫的记忆：三层，其中一层曾经只活在一个会话里

| 层 | 键 | 活多久 | 谁能读 |
|---|---|---|---|
| **会话记忆** `SessionJournal` | (玩家, 猫) | **落盘 7 天** | 只有那只猫 |
| **性格特征** `player_traits` | 玩家 | 落盘 | 所有猫 |
| **在场看板** `PresenceBoard` | 无（全局） | 内存 15 分钟 | 所有猫 |

### 会话记忆：窗口从 6 拉到 20，而且落盘

原来 `turnsPerKey = 6`、提示词只喂 **3 轮**（**一个半来回**），而且**退出即清空、重启即失忆**。
一个跟猫聊了十分钟再回来的人，迎接他的是个陌生人 —— 这读起来像**冷漠**，不像**健忘**。

现在是 20 轮（十个来回）喂给提示词，写进 `agents/profile-memory.db`，**登出不删**：
登出只释放内存，遗忘靠 7 天留存，不靠断线。

> 留存 7 天是刻意的：猫的记忆是聊天日志**已经存着**的那些字的另一个切片
> （`chat/log.db` 里私聊正文本来就存 7 天），不是多出来的一类数据。

**曾经有一层缓存，结果每句话被读了两遍** —— 缓存里是最新的，表里也是同一批，
`recent` 把两边拼起来就重复了。去重需要行没有的身份，于是**干脆去掉缓存**：
`AgentRuntime.ask` 本来就跑在 agent 池上（一次对话 = 一次网络往返），
那里同步写一次索引插入，对玩家的聊天路径零成本。**少一个真相源，少一类读合并的 bug。**

### 记得 ≠ 要说：记忆进提示词的那一行禁令

窗口是提示词里**最诱人的一段文字**：引用过、只关于眼前这一个人、用起来像是「显得聪明」。
三条都是模型伸手去够它的理由。什么都不写，它就会说「你上次说过」——
而这恰恰是让一只猫看起来像**在给你建档**的那句话。

所以约束写了**两遍**，因为它要管两种东西：

- **窗口正下方**（`PromptBuilder.userBlock`）：三条禁令紧贴着引用的对话 —— 不要用
  「你上次说过」「你之前提到」开头，也不要换个说法绕着提；它们是**上下文**不是**话题**，
  让它们影响怎么答，而不是让猫「有话可说」。规则要紧挨着诱惑，不在一屏之外。
- **system 的「怎么回」**：`- 记得 ≠ 提得起。` —— 窗口是空的时候，猫手上还有印象和特征，
  照样可以主动端出来。通用规则不能挂在某个可能为空的数据块上。

> **禁止的是「提」，不是「记」。** 绝对化的「永远不要提过去」会被模型照字面执行：
> 玩家问「我上次跟你说什么来着」，猫答「我不记得」—— 那比原来的献殷勤更糟。
> 所以豁免必须写进提示词（**除非对方自己先提起**），并且由一个测试钉住。

单测断言四条：规则在**窗口之后**而不是之前（紧邻）、豁免存在、历史原文仍在提示词里、
空窗口时不产出这一段（没有东西可禁，就不留空章节）。

### 在场看板：共享「谁在场」，不共享「说了什么」

一只只听玩家跟自己说话的猫，感觉不到有个服务器在运转。最便宜的一步是让它知道
**此刻有人在公屏上说话** —— 只记**事件，不记内容**：谁、说了几句。

`PresenceBoard.note(player, isPublic)` 里的 `isPublic` 是**参数**而不是从频道名推断的，
就是为了让调用点**无法意外把私聊放进来**。看板只有名字和句数，
提示词里那层甚至写着「不要猜他们在聊什么」。

> **共享「发生过什么」和共享「说了什么」是两件事。** 前者是存在感，后者是监视。
> 现在的隐私靠**失忆**实现，而失忆让猫读起来是死的 —— 该做的是换一个不读别人内容的通道，
> 而不是让猫什么都读不到。

写者是 `ChatMessagePublished` 的第二个订阅者，和 `ProfileTracker` 同一个事件、同样一次
内存增量。**又一个必须接上线的接缝** —— 这一轮已经找到三个了。

### 印象门槛保持 3 次

想过把它降到 1，让「同一个玩家」在别的猫那里也存在。读了 `ImpressionPrompt` 之后**放弃**：
它的 KDoc 记着一次实测 —— 只见过一面的玩家，模型编出了「他半夜不睡，去过玩家的农场三次」，
而**那些句子会被别的猫当成事实读**。1 次见面不足以有个印象，3 次才有。

### 印象层：三层记忆里唯一曾经没有写手的一层

`ImpressionService` 之前不存在。`ImpressionPrompt`（119 行，专治上面那次实测幻觉）**零调用者**，
`cat_impression` 表有写手没读者、也有读者没写手，而 `CatSink` 构造 `Question` 时压根不给
`ownImpression` —— 于是提示词里那层**永远是**「(你还没怎么和 Alice 说过话)」。
**三层记忆，当时只有 2 层是活的。**

现在接上了，读手和写手一起：

- **写**：玩家拿到回答**之后**、在 agent 线程上写（`CatSink.answer` 的最后一步）。
  早一步会让一次额外的网络往返卡在「问题 → 回答」之间；晚一步是刻意的。
- **什么时候写**：聊够 [MIN_MEETINGS]（3）次、有特征统计、且距上次写超过 30 分钟。
  那个间隔是硬的 —— 没有它，一个一分钟内问了十次的玩家会买到十次模型调用。
- **花谁的钱**：**主动那条通道**（`Lane.PROACTIVE`），也就是本来为「猫主动开口」预留、
  却因为 `offerProactive` 零调用者而一直空转的那 20%。**从不**动用玩家提问的额度。
- **读**：按 (玩家, 猫) 读，带内存缓存；重启后从库里取，所以「猫记得你」跨重启成立。

**第 3 层（别的猫的看法）故意没做。** 印象是「写给自己看的」，把每只猫的私人笔记默认塞进别人的
提示词，正是这个项目一直拒绝的那种监视。`peerImpressions` 保持为空，直到真的有东西会去**问**
一只猫对某人的看法、且当事人同意。

> **守卫漏了中文数字。** `acceptImpression` 原本只查 `isDigit()`，而它 KDoc 里举的两个例子
> ——「去过玩家的农场三次」「半夜两点」—— **都不是数字**，是汉字，两条都从那道专为拦住它们而写的
> 检查里溜了过去。现在改成 `[数词]+[量词]` 的窄匹配：抓住编造的次数，又不会把「不一定」「一直」
> 「第一」这类正常的印象一起拒掉（拒得太多，守卫最后只会被关掉）。

### 压缩层归谁：印象不能活得比它压缩的东西久

**上一轮刚补上的印象表，是整个插件唯一没有留存期的玩家数据。** `prune()` 只删 `player_report`，
`cat_impression` 和 `player_traits` 无限增长，而 `forgetAll(player)` 写好了却**零生产调用者** ——
也就是说当时**没有任何玩家能要求猫忘掉他**。

而「印象」是聊天原文的压缩产物。于是你刚定的「15 天不登录就删聊天」和它直接冲突：
第 16 天聊天没了，猫手里还留着一句从那些对话里提炼的话。
**压缩层活得比它的来源久，两条保留承诺就互相拆台。**

现在的规则：`agents.impression-days`（默认 15，与 `chat.log-days` 一致），
**时钟是玩家的最后登录时间，不是印象有多旧**：

```
DELETE FROM cat_impression WHERE player = ?   -- 该玩家已被所有猫忘记
```

三点是刻意的：

- **时钟来自 `chat_active`，不来自 `updated_at`。** `updated_at` 只在猫刷新意见时才动，
  所以按它算会让「天天上线、但最近没跟猫说话」的人被忘得一干二净 —— 明明他的聊天还在完整保留着。
- **「查不到」不等于「不在」。** `chat_active` 只认识**日志建立之后**登录过的人；
  把「没有记录」当成「从不登录」，会在升级后**静默清空所有老玩家**。所以返回 `null` = 保留。
- **登录历史的唯一权威是 chat context。** `chat/log.db` 别的 context 读不到（红线），
  所以通过 `ChatDirectoryAPI.lastSeen(player)` 去问，而不是在 agents 那边存第二份 ——
  两份「他什么时候上的线」迟早会不一致，而那正是一条保留承诺变成假话的方式。
  chat context 内部用内存表回答（开库时从 `chat_active` 读一次、join 时更新），
  这样接口是同步的，**不必在定时器线程上等 JDBC**。

清理接在 `DisciplineLoop` 里（已经是每 5 分钟「一个定时器管所有事」，不多加一个）。

### `/meo known`：这些印象是关于你的，你可以看

印象是**模型在你不在场时**从统计量里写的。一整套机制对准一个人，
而那个人从来不知道有这句话存在 —— 留存规则诚实交代了这些字留多久，
却没有任何东西交代「有一句关于你的话」这件事本身。

`/meo known` 用**你自己**的语言列出每只猫对你的印象，以及写下它的时间。
这也是最便宜的检查：如果这一页出现任何玩家会反感的东西，那份反感是可以处理的；
而没有这一页，它就无从提起。

**只读。** 能删的列表是没人敢打开的列表；删除是另一条命令、另一次确认。
一只已经不存在的猫写下的印象**照样列出来** —— 那仍然是一句关于这个人的话。

### `/meo forget <你的名字>`：要删的那条路

```text
/meo forget Steve        # 名字对不上 → 拒绝，什么都不删
/meo forget <你的名字>    # 跑，然后如实报告每张表删了几行
```

**名字就是确认。** 这条不可逆，一条不带参数的 `/meo forget` 离「误删自己的历史」只有一次误点。
打出**自己的名字**是一个「读者读懂了提示、而且确实是这个意思」的检查 ——
比敲一个 `yes` 强，也堵死了「对别人做」的可能。

**权限是 `meowo.chat.use`（`default: true`），也就是所有人，不是只有 op。**
这是刻意的：和 `meowo.admin`（`default: op`）的定位相反。
把「删自己的数据」锁在 op 后面，在任何服务器上都会让普通玩家**永远用不了这条权利** ——
而印象恰恰是模型在他不在场时写下的。`/meo known` 和它同一个权限，
所以「能看到猫记得你什么」和「能删掉」始终是一致的。

即使权限放开，这条命令的**可删范围**也被限制了（见下）：
所有人可用 ≠ 能删所有东西。

**只对自己开放，刻意不提供管理员代删**：遗忘是整个插件里唯一一个
「管理员替别人做」意味着另一个威胁模型的操作。

**如实报告，每张表一个数字**：`玩家报告` 数据库和 `聊天日志` 数据库互相看不见，
所以报告来自两边各自的操作数。`Forgotten` 是**逐表计数而不是一个布尔** ——
一个漏了表还回答「已完成」的隐私指令比直接拒绝更糟，因为玩家会停止检查。

报告里也保留了 unknown：chat context 没起来或者抛异常时，
那一半走 `forget-partial` 并**明说「它删没删我没法说」**，而不是报一个 `0`。
半完成比假装完成好 —— 玩家会以为还有东西留着，会再问一次。

**内存副本也一起丢**（会话窗口 + 印象缓存）：行没了，
但堆里那份还在，能撑到下次重启 —— 足够让一只猫**用自己的话**复述一句
对方要求删掉的话。数据库和堆的生命周期不同，只有 store 看得见前者。

### 什么**不**删：别人写你的，和服务器记的

第一版是 `DELETE FROM player_report WHERE subject=? OR author=?` 加
`DELETE FROM work_order WHERE subject=?`，理由是「删了投诉却留着纪律阶梯的行，不叫删除」。

**方向反了。** `subject=?` 命中的是**别人写的关于他的投诉**，
而投诉刚写入时是 `state = "OPEN"` —— **还没人审过**。
所以第一版实际提供的是：**一个正在被投诉的玩家，打自己的名字，
就能把那条没人看过的指控和它将要爬的阶梯一起抹掉**，然后被如实告知「删了 N 条」。

现在分成三类：

| 数据 | 归属 | 处理 |
|---|---|---|
| 猫的印象、`traits` | 你 | **删** |
| **你提交的**投诉 | 你（是他对别人的话） | **删** |
| **别人写的关于你的投诉** | 别人 | 标记 `FORGOTTEN`，退出使用 |
| **纪律工单** | 管理方 | 标记 `FORGOTTEN`，退出阶梯 |

「标记」不是「保留给你看」：行还在库里（**不重写历史**），
但 `reportsAbout` 不再把它算成指控，`WorkOrderLadder` 的终态集合也保证它**无法被爬升** ——
阶梯不能朝着一个说过「我不想在这儿」的人往上走。

**有东西留下时，命令会说**（`forget-kept` + `forget-kept-hint`，
只在真的留下时出现，不是什么都没有也喊一嗓子）：
「N 条别人写你的投诉、M 条工单没有删 —— 那是别人说的话和服务器的管理记录。
它们已经退出使用，但名字还在库里。要彻底删掉请联系管理员喵。」

玩家分辨不了「删了」和「还在库里」时，这条命令就是在骗他。

**限流不跟着被洗掉**：一个作者一天能提交几条（`countSince`）走
`reportsByAuthorSince`，**不过滤 `FORGOTTEN`** —— 否则被投诉者一执行 forget，
投诉人的配额就刷新了。一个能被第三方重置的限流不是限流。

**刻意不删**：`chat_active`（登录时间）。那是**在场**不是**记忆** ——
忘记某人说过什么，和假装他从未来过，不是一回事；
而且下次上线这行会重写，删了白白让留存扫描失去唯一可靠的信号。

### `topics`：印象提示词里那一行的来源

`ImpressionPrompt.Request.topics` 写着「短话题标签，**绝不是他们的话**」，
但它从建起来就**没有任何来源**，所以那一行提示从来没出现过。

来源是 `TopicTagger` —— 一张封闭词表，纯函数，**零 token**。
不是模型：写印象本身就要一次调用（走 `Lane.PROACTIVE`，那是留给猫主动想说的额度），
再加一次往返只是为了归类；而更要命的是，**分类器和摘要器是同一个幻觉形状**，
而它的输出会贴在那条写着「只写你知道的事」的线**下面**。

它在 `CatSink` 里被调用（`answer` 之后，同一个 agent 线程），
数据是 `runtime.windowOf(...)` —— 会话本来就有的窗口，
**不碰热路径、不新增存储、不受重启影响**。

它没有能力返回玩家的原话：输出的每个字都写在词表里。
这条承诺是**结构性**的，所以不需要信任它每次都做对
（`ImpressionPrompt.Request` 的 `init` 还再挡一次）。
